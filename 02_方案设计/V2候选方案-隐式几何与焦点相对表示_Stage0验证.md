# V2 候选方案：隐式几何与焦点相对表示（Stage 0 可实施验证）

> 创建日期：2026-10-29  
> **状态：研究/实验设计草案，已获授权写入；尚未实现、未训练、未产生实验结果，不是已确定的 Ours。**  
> 主目标：验证“不把显式 Depth/CoC 作为推理必需输入”的几何表示是否值得用于视频虚化。**先检验中间表示，后决定生成架构；暂不改 VAE Decoder。**  
> 本文是方向一（几何与外观潜变量）的一个独立候选分支；方向二（几何记忆驱动视频生成）与方向三（动态 3DGS/4DGS + 光学虚化）仍然保留。文献定位见[跨方向架构调研提纲](../视频虚化生成_跨方向架构文献调研提纲.md)。

## 0. 一句话执行目标与范围

**研究问题**：在给定全清晰 RGB 视频与用户选定的对焦位置/区域时，冻结 VGGT 的**内部中间特征（而非最终 Depth Map）**，是否比单纯 RGB 特征以及 VDA/VGGT 最终深度，更准确地表达“每个位置相对于对焦位置更近、相近、还是更远”，尤其是在细结构、遮挡边界和连续视频中？

这是一个**表示能力探针（Representation Probe）**，不是虚化效果实验。Stage 0 只预测焦点相对几何关系；不训练 ATB、不调用完整虚化生成器、不额外设计 Guided Decoder，也不输出新虚化视频。

**要证伪的假设**：

- H1：VGGT 中间特征包含可利用的焦点相对几何信息，且相较同一 VGGT 的最终深度图有增量价值。
- H2：这些增量价值至少在细结构/边界/跨帧稳定性某项可重复测出，而不仅是更大的编码器和预测头。
- H3（留待 Stage 1）：Stage 0 的几何改善可转化为**真正可控的虚化生成收益**。Stage 0 不能证明 H3。

**当前非目标**：首次提出无深度虚化、首次提出潜空间残差、首次提出几何注意力、首次提出跨帧几何。BokehFlow 已有无显式深度的潜空间虚化/Flow Matching；ATB 已有 VAE Latent 单步虚化、CoC/MPI 条件；BokehCrafter 已有不要求显式深度的参考图/文本视频虚化。不能把“去掉 VDA 输入”本身写成已成立的创新点。

## 1. 与原 V1 的关系

### 1.1 原 V1（保留为显式深度增强候选）

```text
清晰视频 V ──→ Video VAE ──→ z_A ───────┐
             VGGT + Adapter ─→ z_G ──────┤→ Fusion → Δz → z_A+Δz → 旧 VAE Decoder
             VDA → Depth → CoC ──────────┘
```

原 V1 即使加入 Geometry Latent，**仍通过外部预测深度换算的 CoC 向生成器提供可能错误的几何约束**，所以其风险与 ATB 有重叠。原 V1 不废弃，留作 Stage 1 的对照思路。

### 1.2 新 V2 候选（不依赖显式深度图作为推理必需输入）

```text
                           清晰 RGB 视频 V
                               /       \
                              ↓         ↓
                         Video VAE     VGGT
                              ↓         ↓
                             z_A   中间特征 F_G
                                       +
                             对焦点或区域 Mask M_f
                                       ↓
                              Focus Query Interaction
                                       ↓
                           焦点相对特征 R_f (非必需为深度)
                                       ↓
                         Geometry–Appearance Interaction
                                       ↓
                        Video Bokeh Generator（待定）
                                       ↓
                         Bokeh Latent → 原 VAE Decoder
```

候选关系为：

$$
q_f = \operatorname{MaskedPool}(F_G, M_f),\qquad
R_f(x) = H_\theta(F_G(x),q_f),\qquad
\hat z_B=G_\theta(z_A,R_f,K).
$$

- **推理输入权限**：RGB 视频、用户点选/框选/已有可部署算法得到的目标区域，以及相对虚化强度 K；**不允许输入 GT Depth、GT CoC 或由 VDA 预计算的 CoC**。
- **训练/评价权限**：可使用合成数据的真实轴向深度 Z 或独立标注来监督相对关系；这与推理不输入深度不矛盾。
- **输出形式**：最终只需虚化 RGB 视频；没有理由为了模仿 Gen3R 强制输出 Depth/Point Map。Stage 0 的辅助几何预测头仅用于探针和监督。
- **Base + Delta**：$\hat z_B=z_A+\Delta z$ 可保留为 Stage 1 的单独消融，不与 Focus Query 的首次验证捆绑。

**认识边界**：VGGT 特征是从图像推断出的几何先验，并非没有几何估计误差；不显式输出深度不等于几何正确，也不自动具备物理米制焦点控制能力。

## 2. Stage 0：最小可证伪实验设计（优先实施）

### 2.1 数据来源与限制

首先复用已有 Sintel 几何 pilot 的**6 个连续来源、150 帧**，原有划分为：

| 用途 | 来源（现有清单） | 帧数 | 实施要求 |
| --- | --- | ---: | --- |
| 小规模训练试用 | `ambush_4`、`shaman_2`、`bamboo_1`、`bandage_1` | 100 | 沿用现有视频/来源级隔离 |
| 开发验证 | `cave_2`、`market_2` | 50 | 不从开发集选择阈值、结构或超参数后称其独立测试 |

参考：[`configs/ours-sintel-dual-input-v2.json`](../configs/ours-sintel-dual-input-v2.json)、[旧 Student 配置](../configs/ours-student-pilot-v1-20261023.json)、[中央进度](../03_实验记录/当前实验进度与方法论.md)。

**必须核查**：原始 Sintel **轴向深度 Z、有效像素 Mask、RGB 连续帧**是否均可在当前机器读取。旧 pilot 使用的 `d_ref=a/Z+b` 是**向 VDA 输出坐标拟合后的几何参考**，不宜直接作为本次“VGGT vs VDA”主要监督真值，否则可能让 VDA 基线受益。Stage 0 的主标签应从原始有效轴向深度 Z 独立推导；旧 q8/归一化参考仅作为数据链路参考或单独敏感性分析。

Sintel 是小规模合成数据，有动态物体、遮挡与渲染域差异；**只适合 pilot**。若 Stage 0 值得继续，应另补未参与选择的场景来源和实际视频做独立验证。不能把 150 帧视为 150 个独立视频，更不能把已见开发数据当盲测。

### 2.2 输入与焦点选择协议

所有 P0–P3 共享**完全一致的 RGB 帧、图像几何预处理和焦点 Mask `M_f`**。先用预先指定的 RGB 坐标点/小区域（例如固定网格点或预定义框），不利用 GT Depth 选择最容易预测的区域，也不根据模型输出事后调整焦点。

- Stage 0 可以先用**逐帧确定的焦点坐标或固定区域**研究同一帧的相对几何；若要研究整段视频的同一跟焦对象，需提供明确的 RGB 可用跟踪/标注规则，不能把不同帧同一像素坐标当作同一物体。
- 目标区域、像素有效性阈值、区域大小以及采样种子在看预测结果前用训练集预先确定；如焦点区 GT 有效像素不足，则整例标为无效，不暗中换焦点。
- VGGT 的标准预处理可能改变分辨率、宽高比或坐标；输入 RGB、Mask、GT 标签必须使用**同一可复现坐标变换**；边界和无效域不插值为有效 GT。
- 不在当前轮使用 DAVIS 的 GT 主体 Mask 冒充可部署的推理选焦输入；如果用人工点选/框选，应声明为用户交互输入，对所有模型公平开放。

### 2.3 相对几何监督标签

为避免跨场景绝对尺度差异，先针对有效且为正的轴向深度定义：

$$
Z_f=\operatorname{median}_{x\in M_f\cap\Omega_{\mathrm{valid}}} Z(x),\qquad
r_f(x)=\log\frac{Z_f}{Z(x)}.
$$

约定 $r_f>0$ 为该点**比焦点更近**，$r_f<0$ 为**比焦点更远**；$|r_f|$ 小表示深度接近。用**训练集事先固定**的容差 $\varepsilon$ 得到三分类：

$$
y_f(x)=
\begin{cases}
\text{near}, & r_f(x)>\varepsilon,\\
\text{on-focus}, & |r_f(x)|\le\varepsilon,\\
\text{far}, & r_f(x)<-\varepsilon.
\end{cases}
$$

注意：这里的 `on-focus` 仅是**几何邻近类别**，不等于真实镜头的清晰景深范围；真实 CoC 还依赖焦距、光圈、对焦距离与标定。为了避免把多层/透明像素单个 Z 标签当作可靠光学真值，透明/混合/无效像素需单独标记或排除主评分。

标签仅用于训练损失和评价；**P0/P3 的输入不能获取 Z 或 $r_f$**。对 P1/P2，则将其**预测**深度经过同一目标区域的焦点比较，得到预测关系；不允许使用 GT $Z_f$ 做推理时的对焦数值。

### 2.4 四个核心对照（先保持小模型）

| 组别 | 输入 | 预测关系的方法 | 用途 |
| --- | --- | --- | --- |
| **P0：RGB-only** | 冻结 RGB 空间特征 + 同一个 $M_f$ | 同规模 Focus Query + Relation Head | 判断一般视觉特征的能力 |
| **P1：VDA-depth** | 冻结 VDA 预测深度 + $M_f$ | 由预测深度计算关系，阈值只用训练集确定 | 显式深度基线 |
| **P2：VGGT-depth** | **同一 VGGT** 的最终预测深度 + $M_f$ | 同 P1 | 排除“只因换了更强的深度模型” |
| **P3：VGGT-tokens** | **同一 VGGT** 中间 Transformer 特征 + $M_f$ | 轻量投影 + Focus Query + Relation Head | 验证中间特征是否优于最终深度 |

公平性细则：

- P0 / P3 的 Relation Head 尽量对齐结构、空间分辨率、可训练参数量、训练轮数与数据增强；冻结各自预训练骨干。P3 额外的 VGGT 预训练成本、特征维度与显存单独报告，不能称其与轻量 VDA 具有相同端到端成本。
- **P2 vs P3 是关键配对比较**：共用一个 VGGT、同一输入帧和 Mask，只比较最终深度结果与中间特征；同时记录 P3 是否因增加可训练 Head 而获益。可以增加“VGGT-depth + 同容量可训练 Head”的 P2+ 作为严谨性对照，避免把固定阈值规则与学习型 Head 不公平比较。
- P1/P2 要核对原模型输出究竟为深度还是视差、数值大小与远近的方向，并只用训练数据固定必要的单调转换/归一化；绝对尺度不强行直接比较。
- 不将 VGGT 在不同动态帧上的点图视为一定正确的静态多视图几何；记录动态主体和运动相机的失败案例。首次可从模型真实支持的 clip 帧数开始，不预设能直接处理任意长视频。

### 2.5 第一版网络只需轻量关系预测头

先不套 Gen3R 的完整 Geometry Adapter、联合 VAE 或 DiT。最小可实现版本为：

```text
P3:
frames → frozen VGGT → intermediate tokens → spatial projection → F_G
                                                        │
focus mask M_f → masked pooling on F_G → focus query q_f
                                                        │
                      [F_G(x), q_f, feature interaction]
                                                        ↓
                              lightweight Relation Head
                                                        ↓
                          3-class logits / probabilities
```

重点：**Spatial Tokens 与原图像素的对应关系须先核实**。如果提取的是 camera token、全局 token 或跨帧混合 token，不应在没有空间映射的情况下硬 reshape 成深度图。先确认官方 VGGT 返回的层级、patch grid、时序维度及对应分辨率，再选择一组可提取的空间 token；第一版不并行搜索许多层/组合。

监督先用有效像素加权三分类交叉熵或类均衡交叉熵；不叠加 Temporal Loss、Depth Reconstruction、Bokeh Loss 或蒸馏损失。类别不均衡和忽略像素的口径须写入首版配置，不能通过开发结果再修改后仍当作独立比较。

### 2.6 指标与分析

**主指标（Stage 0）**：

1. **Macro-F1 与 Balanced Accuracy**：三类等权，避免“多数像素远景”造成虚高准确率；按每个视频/家族汇总，不只累计全体像素。
2. **细结构和边界分组**：基于训练前固定的 RGB/GT 边界定义和合法有效域，独立报告边缘附近的 Macro-F1；边界定义不能根据各模型输出动态改变。
3. **各类别混淆矩阵**：重点观察把 near/on-focus 错判成 far 的比例；必要时分析近焦区域和遮挡边界单独的失误。

**辅助分析**：

- 按帧、按序列比较是否存在明显抖动；若有**可靠的光流/跟踪和可见性 Mask**，在有效对应位置分析跨帧相对关系变化，但**不能简单规定相邻帧的 $r_f$ 必须相等**：主体/相机移动以及焦点变化都可能使真正离焦关系改变。
- 记录对焦位置切换时 P3 的响应是否符合 GT 近/远类别变化。
- 可视化 `RGB / GT 近-焦-远 / P0–P3 预测 / 有效区域`；既保留成功，也保存典型反例。

**重要限制**：Stage 0 更好的相对几何分类并不直接说明虚化 PSNR、LPIPS、真实边缘质量或时序观感更好。

### 2.7 预先确定的决策规则（建议值，正式实验前写入配置）

在保留相同数据、输入权限和训练预算的前提下：

- **初筛通过的候选条件**：P3 对照 P2+ 在开发来源的平均 Macro-F1 或 Balanced Accuracy 有明确正向差异，且核心细结构/边界子集不退化；理想情况下两个开发来源的方向一致。可预先采用“Macro-F1 +2 个百分点，边界不下降超过 1 个百分点”的**工程筛选阈值**，但它是可调整的事先约定，不是统计显著性或论文证据。
- **暂缓条件**：P3 仅优于 P1、却不优于同一 VGGT 的 P2/P2+；或收益只来自更多可训练参数/泄漏；或动态帧异常明显。此时优先排查标注、空间映射与训练公平性，不直接堆更复杂的 Adapter。
- **后续要求**：真正进入 Stage 1 前，在额外的未用于方法选择的来源上复核方向；两个开发序列不足以说明泛化能力。
- 如果 P3 无独立增益，考虑改进问题定义或转回方向二（场景记忆）/方向三（动态 3DGS），不把 V2 当作必须完成的创新。

## 3. Stage 1：仅在 Stage 0 有依据后启动

**任务**：把有用的焦点相对几何特征加入真正的视频虚化生成器，同时保持既有 VAE Decoder 不变，证明几何表示收益能够传递到 RGB 虚化结果。

候选对照（至少）：

| 组别 | 推理条件 | 核心比较 |
| --- | --- | --- |
| E0 ATB | VDA + CoC / MPI，按原公开协议 | 显式几何基线 |
| E1 RGB-only | RGB + 合法对焦区域/强度，无外部几何 | 纯视觉视频虚化 |
| E2 RGB + VGGT | RGB + VGGT 中间特征，普通融合 | 是否只是增加更强 Backbone |
| E3 RGB + VGGT + Focus Query | 与 E2 其余条件相同，增加 Stage 0 的关系表征 | 专门机制是否有益 |

Stage 1 才需要**清晰/虚化视频配对 GT**、多焦点/多光圈覆盖与控制条件对齐。不能拿 Sintel 深度 GT 直接当虚化真值，不能把参考 CoC 替换实验中的“输出发生变化”当成“输出变好”。Base + Delta 与 Direct Output 另设一次单因素比较：

$$
\text{Direct}:\ \hat z_B=G_\theta(z_A,R_f,K),\qquad
\text{Residual}:\ \hat z_B=z_A+G_\theta(z_A,R_f,K).
$$

BokehFlow 已有相近的无深度潜空间残差/Flow Matching 思想；残差预测不单独声称创新。初期只使用**已确认的可比较训练数据与输入权限**，不默认 ATB 的 Synthetic 数据与新方法具有完全一致的光学参数定义。

正式评价：沿用冻结 ATB 协议的 PSNR、SSIM、LPIPS、FD、RM、FVD、VFID-I 等，补充分焦点、边界和焦点切换的诊断，且保持相同数据划分、分辨率和推理预算的可比性。

## 4. Stage 2：只有出现跨帧专属问题时才引入场景记忆

可参考 [WorldStereo、GEN3C](../视频虚化生成_跨方向架构文献调研提纲.md) 等工作考察几何/场景记忆。候选：

$$
S_{t+1}=U_\theta(S_t,F_{G,t+1},T_{t\to t+1})
$$

目标是区分：几何特征抖动导致的错误虚化 vs 运动、焦点变化带来的**真实**离焦变化。不直接把 `C_t=C_{t+1}` 作为损失；必要的光流/跟踪置信度、遮挡和相机运动要进入约束定义。

只有当 E3 对单帧/短片段有收益、但时序仍出现独特失败时，才考虑时序模块/记忆更新；否则避免无依据地增加复杂度。

## 5. 实施顺序、交付与停止点

### 5.1 第一个工作单元：数据和 VGGT 特征接口检查

在写训练循环前，仅完成以下核对：

1. 读取现有 6 家族 150 帧的 RGB、原始 Sintel Z、有效域和视频级划分；与旧 pilot 的经 VDA 对齐参考保持明确区分。
2. 确认本机有**可使用的 VGGT 官方权重**和执行环境，核对输入帧数、所需裁剪/缩放、空间 patch 映射、中间层 Token 取法，以及 VDA / VGGT 预测深度的数值方向。
3. 固定焦点 Mask 采样规则、$\varepsilon$、分类标签生成规则、输出可视化样例；在正式模型预测前完成数据/标签核查。
4. 检查首版 P0–P3 数据张量形状、坐标一致性、无效像素和训练/开发来源不混用；**不运行大规模模型**。

**交付**：首版小型配置、数据清单与若干对齐检查图/摘要。程序入口建议分别放 `src/` 与 `scripts/`；产物沿用 `outputs/`、`logs/`，小型记录放 `03_实验记录/records/`。不上传视频/权重/大型特征至 Git。

### 5.2 第二个工作单元：Stage 0 最小探针

先比较 P1、P2 和 P3；如资源允许，补齐 P0 和 P2+。首版只选**一组**已核对 VGGT 层级、一个固定关系 Head 和同一组焦点 Mask/数据划分。训练前固定超参数、预算及阈值，避免反复查看开发结果后继续把它称为独立验证。

**交付**：每个来源的主指标表、三分类混淆矩阵、典型成功/失败可视化、训练配置、模型来源和局限说明。Stage 0 结束再决定是否开展 Stage 1；不要自动启动新的视频生成器训练。

## 6. 关联先例与证据入口

- [Any-to-Bokeh：公开实现](https://github.com/vivoCameraResearch/any-to-bokeh)；本仓库[ATB 完整数据流核对](ATB架构数据流与研究切入点.md)。ATB 已在 VAE 潜空间做单步虚化预测，训练目标直接是 GT Bokeh Latent。
- [BokehCrafter（AAAI 2026）](https://ojs.aaai.org/index.php/AAAI/)：视频 RGB + 参考图/文本条件，不依赖额外显式深度推理输入；与本候选需重点比较控制方式与时序结构。
- [BokehFlow（AAAI 2026）官方 PDF](https://ojs.aaai.org/index.php/AAAI/article/download/37431/41393)：无显式深度、预训练几何知识、Flow Matching 与潜空间残差相关先例；本候选不能以这些概念本身为创新点。
- [VGGT 官方代码](https://github.com/facebookresearch/vggt)：重点查中间 Transformer 特征的空间布局和多帧几何适用条件。
- [Gen3R 官方代码](https://github.com/JaceyHuang/Gen3R)：借鉴“几何基础模型内部特征 → Adapter → 可用潜空间”的思想，但**Stage 0 只验证表示，不照搬联合生成或双输出结构**。
- [Vid2Bokeh 项目](https://www.hm-cai.com/vid2bokeh/)：光场训练数据与物理离焦监督先例，主要帮助判断未来 Stage 1 的 GT 质量，不等同于本次几何编码创新。
- 本项目[现有 VDA Student pilot 与失败证据](../03_实验记录/当前实验进度与方法论.md)：几何 MAE 改善未必换来虚化质量提升；B36、B33 反例和 MPI 分区实现核验应保留作为后续问题证据。

**阶段性结论**：当前真正需验证的是 **VGGT 的内部中间几何特征是否能提供超越最终 Depth/CoC 的焦点相对信息**。如果不能，暂不推进 V2；如果能，再讨论其在视频虚化生成网络中是否形成有效的几何—外观交互机制。
