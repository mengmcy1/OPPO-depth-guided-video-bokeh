## 1. 为什么这样定位

### 1.1 现有工作的覆盖范围（检索截至 2026-11-11，并不完整，投稿前需复查）

| 方向 | 代表工作 | 现状 |
|---|---|---|
| 2.5D / 扩散视频虚化 | Any-to-Bokeh、BokehCrafter、VBR、PREX、Generative Refocusing | 多帧聚合、可见性置信度已有先例；每次换焦点都要重新推理 |
| 光场重对焦 | Vid2Bokeh（ECCV 2026） | 静态场景、单图编辑 |
| 静态 3DGS 景深 | DOF-GS、DoF-Gaussian、CoCoGaussian | 逐场景优化，输入为多视角离焦图 |
| 动态 3DGS + 物理光圈 | 4D-GRT（arXiv 2509.10759） | 多视角同步视频，逐场景优化（每场景约 3 小时），用 3DGRT 光线追踪渲染；定位是相机效果数据生成工具 |
| 前馈重建 + 物理景深 | 4D-GRT 附录 G：直接把 MoVieS 的重建结果交给光线追踪 | 未针对虚化训练，只是模块拼接；在 CamVFX-4D 上单目景深 23.48 dB / LPIPS 0.309，多视角为 31.25 / 0.121 |
| 部分遮挡虚化 | MPIB（ECCV 2022）、Dr.Bokeh（CVPR 2024） | 指出前景虚化后会透出被挡住的背景，需要被遮挡层；单图输入，被遮挡内容靠补全 |
| 单图 / 双目前馈两层高斯 | SHARP（Apple，arXiv 2512.10685）、StereoGaussians（arXiv 2609.38592） | 学习式两层高斯，面向近距离新视角；后层由网络补全；不做虚化，不处理视频。StereoGaussians 中按深度直接生成的高斯比学习式预测低 5–12 dB |
| 视频高斯记忆 | StreamSplat（ICLR 2026） | 跨帧持久记忆，面向新视角重建；不保证当前帧像素保真，不做光圈渲染 |
| 深度边缘飞点 | 混合密度深度（arXiv 2606.02552） | 每像素多个深度假设，显著减少边界飞点；可作为几何前端的改进方向 |
| **为虚化训练的前馈动态高斯** | — | 未见 |
| **单目视频中"光圈可见、当前帧不可见"内容的显式建模** | 最接近：Synthesizing Light Field Video from Monocular Video（ECCV 2022），从单目视频合成小基线光场视频，被遮挡内容为隐式处理（具体区别待精读确认） | 未见显式建模；4D-GRT 在局限部分把"用扩散先验补弱观测区域"列为下一步，有被抢先的风险 |

### 1.2 本项目已有的证据（第一轮复现，静态场景）

DoF-NeRF R1（真实镜头 f/4 照片作真值）的分区结果中，四种方法的边界区 PSNR 都比焦内区低约 6 dB：CoCoGaussian 27.1 / 33.3，DoF-Gaussian 26.5 / 33.0，BokehMe 组合基线 25.4 / 31.3，DOF-GS 25.0 / 31.5（各方法完成的场景集合不同，只看量级）。来源：[`round1-regional-R1.csv`](../03_实验记录/records/dof-gs-repro-2026-11-05-round1-regional-R1.csv)。

能得出的判断：误差集中在遮挡边界；全图上 2.5D 后处理与各方法自带的景深渲染只差约 1 dB，所以"三维表示天然更好"不能当前提。局限：只有静态场景、f/4、前景/背景两档焦点，也分不清边界误差来自遮挡还是来自深度不准。

## 2. 整体方案（2026-11-11 重写）

> 11-09 版第 2 节（MoVieS 骨干、覆盖度门控修复、2.7 候选改动）原文已移至[归档](归档路线/路线三_整体方案第2节_2026-11-09版.md)。重写依据为 4.12–4.13 的验证结果；下文的主张、贡献和效果仍是待验证的假设。

### 2.1 一句话主张（待验证）

从普通手持视频出发，逐帧前馈预测两层高斯：**可见层**锚定当前帧像素，**隐藏层**从视频其他帧取回"光圈会看到、当前帧被挡住"的内容；再按薄透镜模型做子光圈物理渲染。网络只负责场景内容，焦点与光圈是用户参数，换焦点、换光圈只需重新渲染。

### 2.2 设计依据（详见 4.13）

| 组成 | 选择 | 依据 |
|---|---|---|
| 渲染 | K 个子光圈离轴投影，按深度合成后在线性 RGB 中平均 | K=64 对 Cycles 真值 52.6 / 53.9 dB（U0）；逐高斯解析模糊快 7–10 倍，但焦外比 K=64 低 2.4–8 dB（L1） |
| 可见层 | 学习式几何 + 颜色锚定当前帧 | 未经学习的按深度反投影在估计深度下出现裂缝，焦内低约 7 dB（S1）；SHARP 两层 + 颜色锚定在两档焦点、两种参考下通过对同深度 BokehMe 的 P1（S1b），深度校准后仍通过（S1c）；MoVieS 多帧拼出当前帧，焦内低 2–12 dB（A1） |
| 隐藏层 | 视频观测记忆 + 光圈条件 Query（候选驱动）+ 几何 / 外观联合修正 | 几何一致时，真实隐藏层近 / 远焦全图 +0.20 / +1.47 dB、可恢复区 +0.98 / +3.19 dB，未校准几何下约为 0（S1c）；收益集中在远焦，即前景虚化后透出背景；S1c 原规则只有 +0.17 / +0.04 dB；S1d 的 R2（来源边缘剔除）收回约 59% / 58% 的可恢复区 MSE 差距；候选投影覆盖约 99.8%，但深度正确的只有约 23%，深度错位与来源边缘混色大量重叠（S1d）；可恢复内容主要来自相机视差（B2） |
| 几何 | 现成深度 / 位姿 + 视频多视角稠密流校准 | GT 位姿下校准后，深度相对误差 19.5% / 12.9% / 17.2% → 6.9% / 8.5% / 8.8%；可见层与隐藏层几何必须一致（S1c 阶梯）；DA3 位姿尺度不一致（E2 阻塞） |
| 评测 | 校准后深度、按目标对焦、Cycles 与 LDR 一致两种参考、高光区单列 | 0.1–0.3% 的过曝像素主导全图 PSNR（R1）；按目标对焦更接近实际使用（R3）；校准对所有方法都有帮助，BokehMe 受益最多（S1c） |

### 2.3 流程

```text
输入：手持视频滑窗 + 点选的对焦主体 + 光圈大小（都可随时间变化）
 ① 几何前端：现成的多视角深度 / 位姿模型（DA3 等）+ 视频多视角稠密流三角化，逐帧校准深度；
    真实视频的位姿可靠性仍待解决（见 4.13、第 8 节）
 ② 可见层（逐帧前馈）：像素对齐的两层高斯；几何（位置偏移、尺度、旋转、不透明度）由网络学习，
    颜色 = 输入像素 + 小残差；边缘处预测 alpha 并分离前景色与背景色（规则版整带排除为负收益，见 P5；需学习验证）；
    邻帧特征只用于稳定几何，不参与可见表面的颜色
 ③ 隐藏层（2026-11-11 第二次修订，细节见 2.3.1）：
    长期观测记忆只存经过验证的真实观测（来源帧 RGB、校准深度、三维位置、局部特征、可信度、来源帧号），
    允许同一位置有多个表面假设；
    按"焦点范围内最大光圈"构造宽松的潜在去遮挡区域 → 从静态记忆取多表面候选（以完整来源观测为单位）
    → 候选驱动的 Query：几何解码（选择、深度修正、尺度、旋转、可信度）
      ↔ 按修正后位置重新投影到来源帧读取外观（真实来源颜色、混色识别、不透明度）；
    缺少可靠候选时走 Fallback（扩大搜索，或交给补全并单独标记为生成内容）；
    隐藏层与可见层共用同一套校准几何；预测结果只进短期缓存，不写回长期记忆
 ④ 物理光圈渲染：K 个子相机离轴投影、保持焦平面对齐，按深度合成可见层、隐藏层与补全，线性 RGB 平均；
    焦点场 F(x) 与光圈 A 为用户参数
 ⑤ 输出：浅景深视频；隐藏层缓存与焦点无关，连续调焦不需要重新推理
```

SHARP 用于第一版与论文实验的可见层（本项目为研究用途，其非商业科研许可满足需要）；只在方法需要时（如第二版混合边缘表示）自行实现可见层；StreamSplat 的记忆思路用于缓存设计，不作为可见层骨干（多帧拼出当前帧会损失外观，见 A1 的 MoVieS 结果）。

#### 2.3.1 隐藏层设计细节（2026-11-11，用户确认；均为待训练验证的设计）

**存储分工：长期记忆存事实，短期缓存存预测。**

| 内容 | 来源 | 能否写入长期记忆 |
|---|---|---|
| 已验证的真实可见表面 | 输入帧 RGB + 多帧一致的校准几何 | 可以 |
| Query 预测的隐藏高斯 | 解码器输出 | 默认不可以，只进当前窗口的短期缓存 |
| 后来被真实观测确认的预测表面 | 新输入帧的观测 | 验证一致后可以 |
| 从未被观测的补全内容 | 生成模型 | 不作为真实观测写入 |

- 隐藏表面在当前帧变为可见时，在当前渲染中去重，并用新观测更新记忆，不删除历史观测；去重靠表面 ID 或局部三维关联，不只靠深度余量。
- 旧条目的失效依据"自由空间证据"：后续帧的光线穿过该位置并看到更远的表面时降权或失效（与 TSDF 融合中的空间雕刻同理）。
- 静态记忆每个位置允许 2–4 个表面假设，按深度或观测方向区分、按可信度剪枝，不强行平均成单一表面（避免把前景色混进背景）。
- 第一版只恢复静态隐藏背景。动态观测不进长期记忆，只用于识别并排除运动物体；静 / 动判定结合多帧运动残差、自由空间证据与不确定度，不只按光流大小。

**记忆的融合方式（2026-11-12，用户确认）：第一版用规则式显式记忆，学习式融合预留。**

"判断哪些观测属于同一表面"可以在两个时机做：

| | 写入时融合 | 读取时融合（第一版） |
|---|---|---|
| 决定时机 | 建记忆时决定一次 | 每帧 Query 读取时决定 |
| 记忆内容 | 融合后的表面条目 | 接近原始的观测，带多表面假设 |
| 跨帧一致性 | 所有帧读同一融合结果，天然一致 | 每帧各自判断，可能不一致 |
| 记忆大小 | 小 | 随帧数线性增长 |
| 出错后 | 原始证据已合并，难以补救 | 证据仍在，Query 可重新判断 |

- **第一版**：13 帧的原始观测存得下，记忆按几何规则建立（同表面判定、可信度加权、多表面假设），融合判断主要交给 Hidden Query；只训练 Hidden Query。
- **预留方向：学习式记忆融合**，即 M_s^(t) = MemoryUpdate_θ(M_s^(t−1), O_t)。三维位置仍显式保存，每个条目增加可学习特征 f_j，条目为 m_j = (p_j, Σ_j, c_j, f_j, q_j, ID_j)；由一个小网络决定新观测与已有条目是否同一表面、合并 / 新建 / 丢弃、各观测的权重与可信度。参考：NeuralRecon（片段级 TSDF 特征的 GRU 融合）、Point-SLAM（显式点位置 + 可学习特征）、SplaTAM（持续维护的高斯地图，RGB-D）、SAM 2（记忆编码器 / 记忆库 / 记忆注意力）。
- **加入条件**（满足任意一条）：用 GT 世界坐标检查，记忆中前景与背景被合进同一条目的比例明显；同一表面被重复建成多条；T-A / T-C 序列中同一表面在不同帧被选成不同内容；需要处理超过一个窗口的长视频。
- **约束**（守住"长期记忆存事实"）：融合网络只在真实观测之间选择与加权，不生成观测之外的几何或颜色；位置修正限制在观测支持的范围内；每个条目保留指向原始观测的引用，融合结果可追溯、可重算。
- **训练方式**（加入时）：用 Blender 世界坐标 pass 给出"是否同一表面"的精确标签，直接监督同表面判定（二分类）、融合位置（回归）与可信度；先单独训练融合，再与 Query 联合微调，不从一开始就端到端联合训练。
- **第一版预留的接口**：条目结构保留可选特征槽 f_j（第一版为空）；保留原始观测引用（来源帧号 + 像素坐标）；数据管线导出世界坐标 pass，用于统计错误合并与重复条目比例。
- 论文中，学习式融合只有在消融中证明明显减少错误合并与跨帧不一致时才写成方法的一部分，否则作为实现细节。

**Query 的两条路径：**

| 路径 | 触发条件 | 做什么 |
|---|---|---|
| Candidate Query | 有可信的跨帧表面候选 | 候选选择、位置修正、颜色融合 |
| Fallback Query（a） | 有真实观测，但没有可信候选 | 扩大空间邻域、尝试其他深度假设或读取原始短期特征，仍可能恢复真实内容 |
| Fallback Query（b） | 所有允许的输入帧都没看到 | 只能依靠先验补全；输出单独的置信度标签，评测时不计为"恢复" |

**光圈可见度与可信度：**

- 候选的光圈可见度用连续量 V̂(g) = (1/K) Σ_k T_k(g)，T_k(g) 为第 k 个子光圈到候选 g 之前的估计透射率。比较必须在同一子光圈视角下进行，不能拿中心视角深度代替；T_k 尽量复用可见层 K=64 渲染的透射率，成本按是否可复用实测。V̂ 用于候选排序和训练加权；最终合成交给 K=64 渲染器，不再额外乘一次可见性。
- 模型可信度 q 表示"这颗高斯是否正确"，物理 alpha 表示遮挡与透射。q 只用于选择、拒绝、融合和触发补全，由候选正确性标签单独监督，不乘进 alpha。

**几何 / 外观联合修正：**

- 依据：S1d 中深度错位与来源边缘颜色误差大量重叠，单因素替换不可加（只换深度在两焦点都是负收益）。
- 候选以完整来源观测为单位（同一来源像素的深度与颜色成对保留），先在观测之间选择，再联合微调，不把属性拆开处理。
- 几何解码更新位置后，重新投影到来源帧读取外观（参考 Deformable DETR 式的迭代参考点更新），避免一直沿用错误位置采样到的颜色；输入多来源光度一致性（同一预测位置在各来源帧的颜色方差）作为一致性反馈。
- 来源边缘做解混与受控选色，不整片丢弃（P5 已显示整片丢弃会损失焦内）；可复用来源帧可见层的边缘前景 / 背景分解。

**与 QuerySplat（arXiv 2608.01186）的关系**：借鉴几何 / 外观双分支解码，以及"输入视角与监督视角分开估计位姿、再对齐"的防泄漏做法；可见层不改成查询式（焦内需要像素级保真）；Query 由潜在去遮挡区域与候选播种，不是自由的可学习查询。

#### 2.3.2 时序一致性：第一版（2026-11-12，用户确认；待验证的设计）

**原则**：同一个静态表面，在整段视频片段中使用同一份三维几何与外观；稳定性主要来自表示方式，时序损失只作辅助。固定渲染输入和采样规则只能消除随机采样带来的抖动；高斯投影的亚像素位移和有限光圈采样在运动遮挡边界上仍可能产生时间走样，所以单独保留渲染器时序基线。

| 闪烁来源 | 第一版处理 |
|---|---|
| 对焦距离抖动（整幅画面模糊"呼吸"） | 用户关键帧点选主体，取当帧校准深度的**轴向**深度，在**逆深度** 1/d_f 上插值成平滑曲线（CoC 由 \|1/z − 1/d_f\| 决定）；CoTracker 自动跟焦预留 |
| 静态区域深度逐帧不同 | 静态区域深度取自记忆渲染；几何前端复用 E1 校准，不另做窗口联合校准（时间平滑确定不了全局尺度） |
| 动态区域深度、边缘 alpha 逐帧不同 | 第一版只用当前帧。不做光流时序滤波：相机坐标下的深度本来就随时间变化，人物边缘处光流最不可靠，平均会拖影。预期 T-A 序列会出现人物边缘闪烁，用来判断第二版的优先级 |
| 隐藏表面选择切换、属性逐帧重新生成 | 表面片段 ID；已确认表面直接读取同一份属性；滞回只用于未确认候选 |
| 补全区域逐帧不同 | 小范围、近似平面的补全锚定到参考视角与估计背景面，标为低可信，所有帧复用；不升级为真实观测 |
| 渲染采样 | 推理时固定 K=64 子光圈位置与权重 |

**两遍流程**（离线精修场景，13 帧上下文一次可得，不按在线 SLAM 逐帧改地图）：

```text
第 1 遍（每个视频片段一次）：输入帧的真实可见观测 → 规则融合建立静态记忆
        （世界坐标、表面片段 ID、多表面假设、来源记录）→ 冻结快照
第 2 遍（逐帧，可以是任意帧，包括非输入帧）：
        当前帧可见 GS（当前 RGB 锚定；静态区域深度取自记忆；边缘只用当前帧）
        + Hidden Query（已确认表面直接读取；未确认候选由 Query 修正，结果进短期缓存；
          低可信补全复用）→ 固定 K=64 渲染 + 当前焦点 / 光圈
```

好处：同一面墙不因处理顺序得到不同属性；不需要在线记忆的状态管理；换焦点只需重渲染；连续帧评价天然落在非输入帧上。长视频以后用重叠窗口 + 关键帧 + 版本化快照扩展（参考 Video Depth Anything 的长视频推理）。

**表面片段 ID**：ID 对应三维表面片段或观测簇，一个片段可对应数量可变的高斯，不给每颗像素高斯分配持久 ID（相机移动后像素与旧高斯不一一对应）；空间索引由体素哈希承担。未确认候选的双阈值初值：启用 q > 0.6，停用 q < 0.4 且连续 2 帧；开发期可调，论文实验前固定。是否被遮挡始终由渲染器按当前几何决定，q 不乘进 alpha；软权重只用于来源观测的融合。

**时序损失**（单帧画质为主，时序项小权重）：

L_err-temp = Σ_t ‖ E_{t+1} − W_{t→t+1}(E_t) ‖₁ ⊙ m_t，E_t = Î_t − I_t^GT

- 固定相机片段和静止区域用不扭曲版本（W 为恒等）：在每个像素上都有定义，不需要对应关系，也就绕开了"离焦像素混合多个深度、没有唯一光流"的问题；
- 扭曲版本只用于单一表面主导的区域（由子光圈首次击中 ID 统计，主导占比初值 ≥ 90%）；
- 推焦片段的真值按同一条焦点曲线渲染；
- 思路与 Video Depth Anything 的时序梯度匹配一致（只在真值变化小的地方约束帧间变化）。

**评价**：
- 序列：T-A 固定相机 + 人物经过静态背景、T-C 连续推焦（含固定焦点对照）优先；T-B 手持 + 静态场景、T-D 曝光 / 照明变化在后续版本补全；
- 指标：按 GT 对应对齐后的误差变化（分区报告环带、主体边缘、焦平面附近、补全区域）；未对齐的帧差之差（衔接 L1 / S1b 口径）；静态区域 CoC 抖动（像素）；焦点相对目标曲线的误差与非预期的高频残差（不惩罚用户有意的快速推焦）；表面片段 ID 切换率（用世界坐标 / 物体局部坐标判定是否同一表面）；接缝误差相对同条件真值；同时报告 PSNR / LPIPS，防止靠过度平滑换取稳定；
- 渲染器时序基线：固定 GT 几何与外观，只让相机和物体运动，测剩余抖动，作为闪烁下限。

**预留（第二版及以后）**：动态区域深度与 alpha 的时序处理（见 2.3.3）；CoTracker 自动跟焦（One-Euro 等平滑）；曝光 / 白平衡对齐（线性空间、带正则的全局通道增益、只在可靠静态重叠区拟合，排除高光截断与动态阴影；接口预留每帧颜色变换）；自由空间失效与在线记忆更新；分层补全或视频补全；短期缓存复用前的历史校验（参考实时渲染的时间抗锯齿，把历史钳制到当前证据范围内）。

**定位**：时序一致性写为 C-3 的性质，即持久表面表示的内生结果，不单列为创新点；论文证据以 T-A、T-C 上与 2.5D 方法、视频扩散方法的闪烁对比为主。

#### 2.3.3 可见层时序与边缘解耦：第二版预留（2026-11-12，用户确认；待验证的设计）

**混合边缘表示（第二版优先级最高）**：需要解混的边缘像素满足 I = αF + (1 − α)B。若仍用"一颗颜色等于原始 RGB 的高斯"，背景色已混入前景颜色，大光圈时再叠加隐藏层背景，就会产生光晕或重复计入。因此这类像素改为"前景色 F + 覆盖率 α + 独立背景表面 B（取自记忆或隐藏层）"，由渲染器统一合成。覆盖率到高斯不透明度与足迹的映射由零光圈重建学出，不直接赋值；非边缘区域保持一像素一高斯、颜色等于 RGB。

| 模块 | 设计 |
|---|---|
| 编码器 | 冻结的单帧编码器（先图像、后视频），必要时小学习率微调 |
| 背景先验 | (B_mem, q_mem, m_valid)：用估计几何下实际建出的记忆渲染到当前帧，带可信度与有效性；GT 背景只作 Oracle 对照 |
| 外观分支 | 当前 RGB 锚定；只在混合边缘预测 F、α；记忆背景只减少歧义（已知 B 时仍是 3 个方程、4 个未知量），不能单独解出 α |
| 几何分支 | 时序特征 + 记忆深度先验 |
| 几何门 U_g | 标签用表面对应 m_corr（刚体：物体 ID + 物体局部坐标，只在单一表面主导的像素上使用）；解码器始终同时接收当前帧特征，门只控制历史特征的掺入量 |
| alpha 门 U_α | 用覆盖率帧间变化监督（MatAnyone 式），作用在特征融合上，不平均最终预测 |
| 分支交互 | 深度断层指示哪里需要解混；alpha 边缘约束几何边界 |
| 记忆—可见层循环 | 固定轮数：第 1 遍建记忆 → 第 2 遍冻结使用 → 第 3 遍可选，只能更新已有真实观测的解释，不把网络推测的颜色当作新增观测；是否保留第 3 遍由一轮与两轮的对比决定 |
| 训练顺序 | 先做背景记忆辅助的单帧边缘解混 → 有效后再加两个门 → 最后小学习率联合微调 |
| 护栏 | 针孔重建损失 ‖Î_pinhole − I_input‖₁；焦内指标不得下降（P5 已显示边缘处理不当会损失焦内） |

**取舍记录**：
- 几何门的"误差型标签"（按历史预测误差判断是否更新）暂不采用：标签依赖网络自身预测，训练中不断变化；先用表面对应标签加上始终保留的当前帧路径，出现错误几何被历史传递时再加；
- 形变网格的 rest position 暂不需要：第二版数据只用刚体运动物体；
- 受控抠图合成数据只在必要时建立：剥离渲染只关闭相机可见性（`scripts/route3_blender_b2.py`），阴影与反射保持可见，剥离背景本身带有前景的阴影，完整场景很可能已满足混合公式；先做重建检验，只对不通过的部分（如半透明、折射）另建；
- 颜色的"稳定参考 + 当前变化"分解放在记忆侧、第三版（可见层颜色本身就是当前帧真值）；记忆中的参考色是归一化参考外观，不等于反照率，不做完整本征分解；
- Layered Neural Atlases 只借鉴"统一参考外观"的思想，不采用其逐视频优化实现。

**定位**：候选贡献是"带三维可见性与来源置信度的背景记忆，协同优化前景边缘外观与隐藏表面恢复"。需要的消融：记忆辅助解混开 / 关；解混后的观测回写记忆一轮 / 两轮；改进必须体现在最终视频虚化指标上，而不只是 α 更准。

**预留研究**：多帧背景约束解混。同一前景点叠在不同已知背景上时，I₁ − I₂ = (1 − α)(B₁ − B₂)，可用多帧加权最小二乘求 α（三角测量抠图，Smith & Blinn, SIGGRAPH 1996）；前提是前景颜色与覆盖率基本不变、背景差异足够大，只用于输入图（全清晰），不用于虚化图。形变网格表面对应用 rest position。

**新颖性边界**：逐高斯 CoC（DOF-GS、CoCoGaussian）、单图两层前馈高斯（SHARP、StereoGaussians）、单图补全被遮挡层（MPIB、Dr.Bokeh）、动态高斯物理相机效果（4D-GRT）都已有先例。本方案的区分点须落在"从视频取回、光圈条件、前馈、时序一致"的组合，以及 C-1 的实际收益上；只有"学习式高斯 + 像素锚定 + 物理渲染"贡献偏弱。投稿前逐一复查。

**2026-11-11 补充**：C-1 的表述收窄为"在光圈潜在可见的多层表面中，利用跨帧真实观测与几何 / 颜色联合一致性，进行可验证的表面查询、修正与重建"。需要证明的是：光圈几何能帮助确定查询对象；Query 能从带来源证据的多帧记忆中选出正确表面；联合修正能减少错误候选；该表示可跨焦点复用并保持时序一致。用多视角光度一致性挑选正确表面本身是多视角立体与基于图像渲染的思路，单独不构成新意。主要威胁：视频补全分层基线（ProPainter 类补背景层 + 分层渲染）、分层深度图补全（3D Photo Inpainting）、4D-GRT 的后续工作。若学习方法相对 R1+R2 只有小幅提升，退路为"简单规则 + 光圈条件分析 + 评测集"。

### 2.5 训练（2026-11-11 第二次修订：第一版网络，用户确认）

第一版只解决"静态隐藏背景的表面对应"，其他部分推迟，等训练中出现明确问题再加。

| 模块 | 第一版实现 |
|---|---|
| 几何前端 | 现有深度 / 位姿 + 稠密流校准，不训练 VGM |
| 可见层 | SHARP + 颜色锚定（S1c 校准后 A-color 做法），预先计算并缓存，不与隐藏层联合训练；颜色锚定逐帧约 12.9 秒（S1b 中位数），效率评价须单独报告这部分成本。**加一个轻量前馈锚定头**：保留 SHARP 几何，颜色在高斯投影中心采样输入图 + 小残差头，用零光圈重建训练；与测试时优化版比较零光圈保真度和 P1，接近则替换以去掉逐帧优化 |
| 静态记忆 | 来源帧 RGB、校准深度、三维位置、局部特征、可信度、来源帧号；只存静态观测；两遍流程，片段内建立后冻结（2.3.2） |
| 焦点 | 用户关键帧点选 + 逆深度插值（2.3.2） |
| Hidden Query | 由潜在去遮挡区域与跨帧候选初始化，数量设上限 |
| Geometry Decoder | 候选选择、深度修正、可信度 |
| Appearance Decoder | 按修正后位置从真实来源帧读取颜色，预测融合与混色识别 |
| 虚化 | K=64，不改渲染器 |
| 动态物体 | 只做静态背景去遮挡；动态观测只用于排除 |

暂不做：完整动态记忆、Fallback 生成、复杂的自由空间更新、可学习 PSF 或新渲染器、真实视频微调、可见层时序与边缘解混（第二版，2.3.3）。

**输入与监督：**

- **位姿扰动（2026-11-12）**：S2b 的混合输入加入逐帧旋转 / 平移噪声与尺度漂移，幅度先参考 E2 实测误差、E2′ 选定位姿方案后更新；扰动加在**深度校准之前**，使校准深度带上位姿误差的真实影响；E2′ 定案后在留出场景用估计位姿评测一次。
- 训练输入几何以校准后的估计深度为主；扰动以"校准前位姿扰动"为主。若另加深度扰动，必须加在**可见层与候选共享的几何**上，不只扰动候选（只扰动候选时两边误差互不相关，与真实情况不符）。前馈锚定头可用之前，每个场景预先计算 3–5 组位姿扰动并缓存可见层，不在训练中实时扰动。GT 可见几何只用于训练最早期的短暂热身和调试上界。理由：S1d 的困难都出现在估计深度下，只在 GT 几何上训练，网络会学到一个更简单的、不同的问题。
- **隐藏层标签按子光圈光线定义（2026-11-12）**：用 GT 几何确定 K 条子光圈光线各自击中的表面（对 Blender 导出的网格做 trimesh 射线求交，复用 `scripts/route3_blender_b2_full_geometry.py` 的 `aperture_full`；标签先用 K=16）。光线经焦平面对应点射出，击中的表面随对焦距离变化，而训练时焦点随机取，因此每个目标帧按一组焦点计算：2 档评价焦点 + 若干个在该帧场景深度范围内按逆深度均匀取的训练焦点（初值 4，按实测成本调整），光圈取最大的 f/1.4；f/2.0 只在评价焦点上计算（2026-11-12 补充）。标签拆成两个：
  - **内容是否正确**：用**来源像素自身的 GT 世界坐标**（来源帧世界坐标 pass）判断它是否就是某条子光圈光线击中的表面点，按命中光线比例加权；与深度估计误差无关。不再使用"深度容差 2%"的口径：校准深度本身有 7–9% 误差，按 2% 判定时 S1d 只有约 23% 的候选算正确，可信度会被训练成拒绝大多数候选；
  - **放在哪**：目标不用 GT 绝对深度，而是与可见层处于同一（估计）几何坐标系。在环带周围窗口内，用可见背景像素拟合"GT 视差 → 估计视差"的局部仿射映射，把 GT 隐藏视差经此映射作为目标（局部尺度接近 1 时即退化为"估计背景视差 + GT 视差差"）。依据：S1d 只换真实深度为 −140% / −121%；S1c 中 GT 几何的隐藏层配校准可见层，近焦焦内低 5.4 dB（远焦未下降）。
  - 深度与颜色损失只在对应光线上计算。原因：只用第一层剥离隐藏面作标签，会把对部分子光圈正确的候选标成错误（S1d 替换审计中 67–77% 的匹配候选来自第一层隐藏面以外的物体；该审计本身不能区分"选错"与"标签不对"，但按光线定义在原理上成立）。每个环带位置输出 2 个隐藏高斯，第二个不需要时不透明度为 0。
- 监督分两步：先用剥离隐藏层真值（颜色、深度）与候选正确性 / 子光圈可见性标签直接监督；隐藏层有效后再加 K=64 渲染损失（L1 + LPIPS，按光圈可见度加权）。K=64 训练成本较高，第一版不压上去。
- 目标帧的隐藏层真值只作监督，不进入记忆与 Query 初始化。
- 时序：有连续帧真值的片段加小权重 L_err-temp（2.3.2），单帧画质仍是主要目标。

**对照**（相同输入帧、相同隐藏区域，公开各自的计算成本）：R1+R2 规则（以 S1d 中间结果作开发参考；论文评价时在独立场景用冻结协议重比）、轻量候选融合、完整 Query 解码。

**实现顺序（2026-11-12）**：试点场景一出来，先在其上跑 R2 与视频补全分层基线，量出估计几何、新场景下的规则水平，再写网络。第一版先实现**轻量候选融合**；它达到成功参考线，就不再加 Transformer 与邻域注意力，C-1 表述为"光圈条件的检索 + 学习式融合"；达不到再升级为完整 Query 解码。

**开发期检查**（融入开发，不单列正式实验）：无标签泄漏；小批量前向 / 反向正常、损失下降；固定留出场景，观察是否恢复正确的隐藏表面；评分沿用 S1d 脚本与区域定义，以便与 R2 直接比较；**误激活率**必看：在没有任何子光圈光线需要隐藏内容的位置，不透明度超过阈值的隐藏高斯所占比例及其对焦内的影响（环带约占画面 29%，真正需要隐藏内容的约 5%，直接关系焦内护栏）。

**最小边缘解混（2026-11-12，提前，纳入投稿范围）**：S2a 证明隐藏层有效后做，不训练。对记忆背景可靠的可见层边缘像素，以 B_mem 与邻近前景内部颜色作为 F 的先验，按闭式公式估计 α 与 F；边缘高斯颜色改为 F、不透明度由 α 给出，背后由隐藏层提供 B；用零光圈重建与焦内护栏检查，看远焦可恢复区能否收回 S1b 中的 0.95 dB（与 Query 能争取的空间同量级、同区域）。"同一份记忆同时服务隐藏层取回与可见层边缘"只有在最终虚化指标改善时才写成贡献。

**转向点**（不预注册）：训练 1–2 周后，若在留出场景上仍明显达不到 R2，停下重新判断，不继续叠加模块；聚合不是瓶颈时，转为"规则 + 光圈条件分析 + 评测集"，或转向高光方向。

**成功参考线**（开发参考，不预注册）：在留出场景、估计几何下，差距收回比例达到约 75–80%（R2 约 60%），或远焦全图比 R2 高约 0.3 dB 以上。R2 必须在同样的新留出场景、同样的几何输入下重跑，不沿用 B2-high 的数字。落在失败线与成功线之间时，按上面的退路处理。

**流程**：预注册只用于论文主表和关键消融；开发迭代只记录、不冻结判据。

**训练课程（2026-11-12，用户确认）**：参考 BTimer（先静态、再动态，后续阶段保留静态数据，分辨率与上下文逐步增加）、Video Depth Anything（冻结图像编码器，只训练时空头）、StreamSplat（静态编码器训练后冻结，再训练动态部分）、AnimateDiff（时序能力作为独立适配器）。

### 2.6 实验主线

- **受控评测**：Blender（5.4）；校准后深度、按目标对焦、Cycles 与 LDR 一致两种参考、高光区单列；
  - **两种对焦协议（2026-11-13）**：**P2 目标焦点**为主（S1c 起的冻结协议）：在每个方法自己用于渲染的完整几何里，对焦到主体单表面主导、高置信区域的稳健深度，衡量"点选主体后主体清晰、其余按相对深度虚化"的效果；**P1 物理焦点**为辅：用每帧拟合的"真值视差 → 估计视差"映射，把真实焦平面距离换算到方法的坐标系，主体深度估错时主体会被如实渲染模糊，衡量物理准确性。所有方法（含 BokehMe）统一使用两种协议；"搜索使主体 CoC 最小的焦点"只作对照，不作默认规则（它与 P2 同属目标焦点，只是实现不同）。
- **主要对比**：BokehMe（校准深度）、R1+R2 规则检索、视频补全分层基线（ProPainter 类补背景层 + 分层渲染，不需训练，尽早运行以判断 C-1 的定位）、3D Photo Inpainting（分层深度图补全）、MPIB、Dr.Bokeh、Any-to-Bokeh、SHARP + 物理渲染、视频高斯 + 物理渲染；Vid2Bokeh、PREX 视开源情况而定；
- **消融**：见 2.4；
- **时序评价**：见 2.3.2（T-A、T-C 优先；渲染器时序基线作为闪烁下限）；
- **真实视频**：DAVIS 与手机实拍，做定性比较与用户研究；DoF-NeRF 真实镜头数据作为重对焦参考；
- **效率**：在 4090 D 上统一测量，重点报告"换一次焦点或光圈的边际成本"；第一版可见层的颜色锚定是逐帧优化（约 12.9 秒 / 帧），须与 Hidden Query 的推理耗时分开报告，不能只报后者。

## 4. C1：前提验证（不训练）

> 2026-11-10 三次修订：本节整体重写为统一的区域协议、Oracle 协议、统计与决策规则和执行阶段。核心风险是评价方法把有效方法误判为无效，而不是 M2 算法本身。

按 AGENTS 2.4 说明。

### 4.1 要回答的问题（按顺序）

1. **是否存在可测的三维虚化优势？** 在外观尽量匹配的条件下，三维光圈渲染相对 2.5D 虚化在可恢复区域有多大差距（O1 对 O2）？其中多少来自隐藏表面（O1 对 O4）？
2. **MoVieS 的输出里是否包含被运动物体挡住的背景？** 原生聚合为什么没有用好它（重影诊断，M1-cur 对 M1，静态来源对背景板）？
3. **我们的融合能否比原生聚合更好？** 同时不能损害焦内区、静-静带和时序一致性（M2a / M2b 对 M1，M2c 对 M1-long）。

### 4.2 数据、划分与输入协议

- **数据**：CamVFX-4D，每个视角当作一段单目输入。P1 已确认：
  - 每场景只有一组景深参数，都是 f/0.5；光圈半径 **2–5 cm**（box、plant 为 20 mm，2 cm；ball、basketball_2、cat、cube、lego 为 35 mm，3.5 cm；basketball_1 为 50 mm，5 cm）；
  - 所有视角机位固定；没有逐帧深度、掩码和 .blend，只有一份时间未知的静态网格。

  因此本数据只能检验**固定机位下运动物体造成的遮挡**。静态前景挡住的静态背景在任何帧都取不回，只能靠补全。光圈远大于常见设置（50 mm f/1.8 约 1.4 cm），属于极端条件；相机运动、多焦点 / 多光圈、常见光圈由 5.4 的 Blender 场景补齐，正式结论不能只依赖 CamVFX-4D。
- **场景划分（实验前固定，看过测试集结果后不再调整）**：

| 用途 | 场景 | 说明 |
|---|---|---|
| 开发集 | plant、cat | 覆盖 20 mm 与 35 mm；P1 去遮挡占比差异明显 |
| 测试集 | ball、basketball_1、basketball_2、box、cube、lego | 只用于最终评价 |

  - box 的 P1 去遮挡占比只有约 0.68%，保留在测试集；若实际可恢复区域不足，按事前冻结的最低像素规则单独报告，不临时剔除。
  - 开发集可以调整：背景板与运动掩码阈值、M2 动静划分与可见性过滤参数、CoC 标定、Oracle 检查，以及成功判据。在动 M2 测试结果之前，可以根据背景板质量和有效像素数检查开发集是否合适。

### 4.3 组别

三维组（M1-cur、M1、M2a–c、M1-long、O1、O4）使用同一个光圈渲染器、同一 K、同一尺度对齐。M0、O2、O3 是 2.5D 方法（BokehMe），渲染实现不同，但镜头参数、CoC 约定、RGB 数值范围和评价协议与三维组统一。除 M1-long、M2c 外，MoVieS 各组都来自**同一次前向推理**。

| 编号 | 方法 | 作用 |
|---|---|---|
| M0 | MoVieS 当前帧深度 + BokehMe | 2.5D 基线 |
| M1-cur | 只保留当前帧来源的高斯 | **当前来源消融**。这些高斯已经过跨帧注意力，不是单帧重建基线 |
| M1 | MoVieS 原生：所有输入帧的高斯形变到当前时刻 | 4D-GRT 单目方案，直接基线 |
| M2a | M1 + 静 / 动态来源筛选（静态取全部来源，动态只取近邻来源） | 筛选的作用 |
| M2b | M2a + 可见性过滤 | 过滤的作用，同时检查误删 |
| M1-long | 跨多次推理覆盖长窗口，原生高斯直接合并 | M2c 的同预算对照（输入帧数、推理次数、时序条件相同） |
| M2c | M2b + 长窗口融合 | 和 M1-long 对比，区分"看到更多帧"与"融合设计" |
| O1 | 网格几何 + 对应时刻颜色（仅优化颜色）+ 光圈渲染 | 理想几何下的三维表示 |
| O2 | O1 自己的针孔渲染 + 同一中心深度 + 2.5D | **主要的公平对照**（外观匹配） |
| O3 | 数据集真实针孔图 + 同一中心深度 + 2.5D | 衡量重建外观的代价 |
| O4 | O1 去掉中心视角不可见的表面，空洞用固定颜色合成 | 同一渲染器下隔离隐藏表面的作用；只作诊断 |
| M3 | 多视角优化参考（每时刻 50 视角重建） | 参考上界，不称 GT；在开发场景小规模试点后再决定是否扩展 |

M2 各机制做成独立开关，一次执行跑完全部组合：开发时看累加式（M1 → M2a → M2b → M2c），论文消融表用逐项去掉式。静 / 动态划分要在多个查询时刻上比较同一高斯的位移变化，不能只看单个查询时刻的绝对位移。

### 4.4 区域协议

所有掩码独立于被测方法得到，不能用 MoVieS 的输出推导。每个掩码都要附带置信度、有效像素数和失败标记。

- **背景板（50 帧参考）**：每个视角对 50 帧针孔图逐像素取时间中值（线性 RGB），并记录每个像素与背景板一致的帧数。背景板是**估计值，不是真值**；长期被挡的背景、阴影变化和反射都会影响它，"背景板有效"不等于颜色和几何都准确。
- **运动掩码 M_s**：每帧与背景板差异超过阈值，再做形态学清理；阴影、反射被纳入的情况单独记录。
- **实际输入下的可恢复性 R_t**：设实际输入帧集合为 S_t。对像素 p 的光圈足迹内、在时刻 t 被运动物体挡住的背景像素 q，若存在 s ∈ S_t、s ≠ t 使 q ∉ M_s（且背景板在 q 有效），则 q 可恢复。逐像素可恢复比例 ρ_t(p) = 足迹内可恢复的被挡背景像素数 / 足迹内被挡背景像素数。50 帧的结果只作参考；M2c / M1-long 要按长窗口的 S_t 重新计算，两组在同一区域上比较。
- **光圈去遮挡几何代理 D_t**：静态部分用网格深度（对任何时刻都成立）计算光圈足迹；运动物体深度未知，按场景最近深度取保守的最大 CoC 半径；足迹与 M_t 边界相交（物体内外两侧）的像素构成 D_t。
- **目标区域**：
  - **M_C1_proxy(t) = D_t ∩ {ρ_t ≥ 阈值}**：C1 的主评价区域。它是代理掩码，不称"真实可恢复去遮挡掩码"；
  - 动态不可取回带：D_t ∩ {ρ_t < 阈值}；
  - 静-静带：网格加光圈求交得到的去遮挡像素，扣除运动物体足迹附近的部分，只用作护栏。
- **背景板的诊断用途**：MoVieS 静态来源高斯的针孔渲染在 M_t 内与背景板比较（问题 2）；MoVieS 判为动态的高斯投影与 M_t 的 IoU（动静划分是否准确）。
- 背景板不干净的场景（运动幅度小或长时间静止）要标记，并按 4.6 的规则处理。Blender 场景的逐帧几何真值（5.4）用来核对背景板与掩码的误检率。

### 4.5 Oracle 协议

1. **时间对应**：用网格渲染针孔图，与该视角 50 帧逐帧比较，记录误差曲线和最小误差的时刻。**如果无法确认对应时刻，就不出动态区域的 G**；只在静态背景上得到的结果不能替代动态可恢复带的 G，动态检验交给 Blender。
2. **O1 外观对齐**：几何来自网格（可增加视角或直接从网格表面采样，以提高覆盖）；颜色取对应时刻，在该时刻用 50 个视角的针孔图**只优化颜色、固定几何**。必报覆盖指标：目标区域内的 s_hole、有效光圈采样比例、几何覆盖率。s_hole 接近 0 只是必要条件，不代表恢复的内容正确。
3. **O2 / O3 / O4**：按 4.3 的定义渲染。O4 的空洞合成颜色固定并写入记录。
4. **CoC 统一**：由数据集的焦距、f 值、对焦距离、深度和相机标定计算物理 CoC。仓库现有 BokehMe 适配器使用"官方 gamma2.2 + defocus_scale10"约定，要在**开发集**上把它映射到物理 CoC，冻结后用于所有评价；不在评价场景上逐场景寻优。O1、O2、O3 和 M0 使用相同的光圈定义、焦平面约定、RGB 数值范围（线性 / sRGB 明确记录）和评价掩码。
5. **解释口径**：
   - O1 − O2：外观尽量匹配时，三维光圈积分相对 2.5D 虚化的差距；其中还包含两者在边界混合、模糊核和 alpha 处理上的差异，**不是**纯粹的隐藏内容收益上限；
   - O1 − O4：同一渲染器下，隐藏表面的作用；
   - O2 − O3：重建外观的代价。
   - **G** 定义为开发集上 M_C1_proxy 内 O1 − O2 的合并 PSNR 差，只作参考，不作数学上限。

### 4.6 统计与指标

- **合并 PSNR**：RGB 归一化到 [0,1]，在每个场景内部把所有有效时刻、有效像素的平方误差合并后计算 PSNR，再对场景求平均，避免运动面积大的场景主导结果：

  PSNR_pooled = −10·log10( Σ_t Σ_{p∈M_t} Σ_c (Î − I)² / (3·Σ_t |M_t|) )

- **最低有效量**：每个场景同时满足累计有效像素数与有效时刻数的下限才算有效场景；候选值为至少 1,000 个像素、至少 3 个时刻，在开发集上检查后与判据一起冻结。达不到的场景单独报告，不并入平均。
- **LPIPS / SSIM**：窄带区域在固定大小的 patch 或包围盒裁剪区域上计算，并说明局限；不把掩码外像素清零后当作标准 LPIPS。
- **报告区域**：全图、边界、焦内、焦外、M_C1_proxy、动态不可取回带、静-静带；跨帧闪烁；s_cur / s_other / s_hole 在各区域内的分布只作机制分析。
- **焦内护栏（三层）**：M1 对 M0（三维重建与光圈渲染是否引入焦内损失，必报，并决定以后焦内是否直接取输入像素）；M2b 对 M1；M2c 对 M1-long。另报 M0 对输入针孔图的焦内差距。

### 4.7 决策规则与人工停点

- **A2 硬性停点**：开发集上的区域划分、Oracle 四组、G 和统计可靠性检查完成后，执行端必须汇报并暂停。用户确认最终成功判据、有效场景和评价协议之后，才允许在测试集上做 M2a / M2b 的正式评价。此前可以在开发集上做方法开发和必要的最小正确性检查。
- **对 G 的解释**：
  - G 可靠且明显为正：本数据有值得检验的三维虚化优势，进入 A3；
  - G 很小或为负：先检查外观对齐、几何覆盖、2.5D 标定和区域掩码；
  - G 不可靠（时间对应失败、覆盖不足、有效像素不够）：不据此否定研究方向，动态检验转向 Blender。
  这里停下的是"自动进入正式评价"，不是整个路线。
- **成功判据的形式**（候选，A2 时与用户一起确定数值）：
  - 主指标：测试集 M_C1_proxy 内的合并 PSNR 与 patch LPIPS；
  - M2b 相对 M1、M2c 相对 M1-long 的提升不小于 A2 时冻结的门槛（候选为 min(0.5 dB, 0.3·G)），同时 LPIPS 下降；
  - 以独立场景计的同向比例（basketball_1/2 合并计为一组）达到冻结的比例；
  - 护栏：焦内、全图、静-静带相对各自对照下降不超过 0.2 dB，跨帧闪烁不变差。
- **达标**：进入 S1 / S2 训练。**不达标**：根据 Oracle 与重影诊断判断是"没有可测优势"、"MoVieS 没重建出来"还是"融合方式不对"，查清之前不开始训练。

### 4.8 结论边界

合成室内场景、512²、单一且极端的景深参数（f/0.5，光圈半径 2–5 cm）、固定机位，只针对运动物体造成的遮挡，样本为 6 个测试场景（其中两个可能共享资产）。结论只适用于这一条件。

**结论分三层**：

- **已观察到**：在当前数据、实现和评价协议下，MoVieS 全帧三维渲染相对 M0 有显著焦内质量差距（plant 约 12.2 dB）；差距来源尚未隔离，可能来自模型固有的多来源依赖、透明度与几何表示、渲染接口或输入数据条件，暂不能全部归因于前馈三维重建能力不足。当前基于位移阈值的动静划分与代理运动掩码一致性较差（缺真实动态表面 GT，暂不归因于运动头本身）。在这样的重建底座和现有代理区域下，M2a / M2b 没有表现出净收益，plant 焦内下降 1.06 dB，护栏未通过；现有代理区域（与第 1 帧网格去遮挡区重合仅 10–29%）和单时刻 Oracle 不足以可靠测量隐藏表面的收益。
- **待证实**：用原图保持可见外观、用跨帧三维几何补隐藏层，是否确实优于现有 2.5D 虚化。
- **决定是否继续投入**：在 Blender 几何真值和可靠隐藏层下，这种提升能否在多个时刻、焦点和光圈下稳定存在，同时兼顾画质与时序一致性。

**补充 Oracle 组**（所有三维组使用同一光圈渲染器、同一 K；2.5D 组统一镜头参数与评价协议）：

| 编号 | 可见层 | 隐藏层 | 用途 |
|---|---|---|---|
| O5 | 真实针孔图 + 中心深度，反投影成高斯 | 无；剩余透射率乘固定的 LaMa 填充函数 C_fill（见 B2 部分） | 只有可见层的三维渲染 |
| O6-50（CamVFX-4D） | 同 O5 | 50 帧背景板 + 正确的背景深度 | 可行性探针；用了全部 50 帧信息，**不能**当作 13 帧前馈方法的上限 |
| O6-13（CamVFX-4D） | 同 O5 | 只由 13 帧输入构建的背景板 + 正确的背景深度 | O6-50 − O6-13 即 13 帧输入协议损失的部分 |
| O6-GT-all（Blender） | 同 O5 | 所有被挡表面的真实几何与外观 | 理想隐藏层 |
| O6-GT-rec（Blender） | 同 O5 | 只保留在其他 12 个输入帧中露出过的被挡表面 | **可恢复表面的 GT Oracle**：用真实几何与外观，只筛选可恢复表面；不代表实际模型必然能达到的上限。O6-GT-all − O6-GT-rec 是两者的质量差，**不代表**可取回部分的占比；占比另行统计（见下） |

O5、O6 依然有反投影带来的孔洞、离散采样和 alpha 合成误差，**不是完美的光学 Oracle**。

**O5 / O6 的合成规则**（O6 − O5 只反映"加了隐藏层"的前提）：

- 每条子光圈光线上，把可见层与隐藏层的高斯**合在一起按深度排序**做 alpha 合成；不假设隐藏层整体位于可见层之后（倾斜的子光圈光线可能先打到隐藏背景，再打到更远的可见背景）。合成完成后，剩余透射率乘以填充色，再对 K 条光线取平均：

  C_ray = Σ_i(按深度排序) T_i·α_i·c_i + T_all·C_fill，C = (1/K)·Σ_k C_ray,k

  O5 用同一式子，只是没有隐藏层。**背景延拓不能作为不透明层先合成进去**，否则会挡住隐藏层。
- **填充色 C_fill 是两组共用的同一个函数**：取光线在局部背景深度处的点，投影回中心视角，在固定的 LaMa 背景填充图上取色。填充图、填充掩码、光圈采样、K、颜色空间在 O5 与 O6 之间完全相同。

**覆盖比例**（与 PSNR 差分开报告）：在光圈去遮挡区内，统计被挡表面中"可恢复表面"的比例，以及光圈光线中命中可恢复表面的比例。

**解释口径**：

- O6 − O5：同一渲染实现下，加一层隐藏层的边际作用；
- O6 − O3：混合渲染与"理想中心深度 + 2.5D"的总体差距，同时包含渲染器、深度处理和隐藏层三种差异，**不是单因素消融**；
- O1 − O4：现有三维表示中隐藏表面的诊断作用。

**隐藏层的构建**：

- **背景深度**：运动物体后面的中心深度是前景的深度，不能直接当隐藏背景深度。
  - CamVFX-4D：网格对应第 1 帧并包含运动物体。沿射线跳过运动物体部件，取下一个静态表面的交点；运动部件可以用"网格连通分量投影与 M_1 重合"识别，或对闭合物体做多次求交越过前后两个表面。不可靠时，O6 只在静态背景完全确定的像素上报告。
  - Blender：直接给出。
- **Blender 隐藏层外观**：删除前景物体再渲染会改变阴影、反射和间接光照。改为在 Cycles 中**关闭遮挡物的相机射线可见性**，保留其阴影、反射和间接光照，得到同一光照下时刻 t 被挡表面的真实外观。表面可见性判断沿用 B1 已验证的稳定表面 ID、局部坐标和射线首交点检测。**正式虚化真值仍用完整场景的 Cycles 景深渲染**，不把隐藏层渲染当作最终真值。

**评价区域**：

- CamVFX-4D 第 1 帧：**网格推导的去遮挡区**（比宽代理区域可靠，但不等同于 Blender 原生几何 GT），拆成"靠近运动物体的部分"与"静-静部分"；同时报告原代理区域的结果以便对照。
- Blender：真实光圈去遮挡 GT 与跨帧可恢复性 GT。

所有结果都要报告：合并 PSNR、patch LPIPS、区域占整幅画面的比例、全图影响和可视化。

**两级转向判据**（预先登记；0.5 dB 为探索性参考阈值）：

| 阶段 | 条件 | 决策 |
|---|---|---|
| CamVFX-4D 探针 | O6 − O3 < 0.5 dB，且 patch LPIPS 无改善 | 记为弱信号，不再扩大该数据上的 Oracle |
| CamVFX-4D 探针 | O6 − O3 明显为正，且 O6 − O5 也为正 | 保留隐藏层假设，转 Blender 验证 |
| Blender GT | 多个时刻、两档焦点下，真实隐藏层相对合理 2.5D 基线仍无稳定收益 | 考虑降低去遮挡补全在论文中的优先级，重新选择主要贡献 |
| Blender GT | 隐藏层质量与虚化质量稳定改善，护栏可接受 | 继续混合渲染研究与后续训练 |

**"稳定收益"的量化（历史候选，现行 B2-only 规则以 4.11 为准）**（建议值，执行 Blender 评价前冻结；2026-11-10 补充为四层判据框架，见 B2 部分，0.5 dB 与 75% 保留，LPIPS 候选 ΔLPIPS ≤ −0.01，比较对象增加 Dr.Bokeh-GT）：在真实动态光圈去遮挡区内，O6-GT-rec − O5 与 O6-GT-rec − O3 都为正，并且在"代表帧 × 焦点 × 光圈"的所有组合中至少 75% 同时满足；合并 PSNR 均值 ≥ 0.5 dB，或 patch LPIPS 明显下降。若局部收益明显但区域占比很小，全图指标难以体现，论文须依靠局部指标加用户研究。

光圈越大，去遮挡区越宽，但 PSNR 收益不一定单调增大（更强的模糊也会掩盖纹理误差），所以不能只凭 f/0.5 的结果下结论，Blender 上需要比较多档光圈。

**B2 小规模范围**（2026-11-10 修订：原场景 CoC 过小，拆成两个场景）：

原 B1 场景按薄透镜计算（50 mm、36 mm 传感器、512 px，对焦 5.3 m、物体 8.4 m），CoC 半径只有 f/0.5 约 2.5 px、f/1.4 约 0.9 px、f/2.8 约 0.45 px，小于 CamVFX-4D plant 的最大约 11 px。在这种场景下即使 O6 有完美隐藏层，也难以显出优势；测得 O6 − O5 很小只能说明去遮挡需求不足，不能说明隐藏层没有价值。作为参照，对焦约 1.5 m、背景约 5 m 时为 17.2 / 6.1 / 3.1 px。

| 项目 | 内容 |
|---|---|
| 场景 B2-low（对照） | 保留 B1 原场景，作为低 CoC 对照，结果照常报告 |
| 场景 B2-high（主实验） | 新建高 CoC 版本：目标 f/1.4 下前景或背景 CoC 半径约 5–10 px、f/2.8 约 3–5 px，f/0.5 只作压力测试。可从对焦约 1.5 m、背景约 5 m 着手，同时调整相机运动、物体位置和构图，不能只改焦点参数。保留棋盘纹理，增加自然纹理和更细的非周期纹理；必须同时包含动态物体造成的遮挡和静态遮挡 |
| 场景有效性 | 不只看 CoC 半径，还要确认真实子光圈光线确实揭示了中心视角看不到的表面。每个配置记录去遮挡区内的 CoC 分布、真实去遮挡覆盖率和区域像素数；**去遮挡区内 CoC 中位数低于约 3 px 的组合从主要成功率统计中单列**（仍报告），该规则在看 O5 / O6 结果之前固定 |
| 采样 | 场景修改后重新做 Cycles 采样收敛，原 512 / 2048 spp 不直接沿用；用不同随机种子的重复渲染估计真值噪声，作为 LPIPS 门槛的噪声参照 |
| 输入帧协议 | 60 帧中按等间隔取整得到 13 个输入帧：1, 6, 11, 16, 21, 26, 30, 35, 40, 45, 50, 55, 60 |
| 景深 RGB | 3–5 个代表帧，**只从这 13 个输入帧中选**，覆盖不同遮挡状态；O5 只用目标帧自身的针孔图，O6-GT-rec 只用另外 12 个输入帧的可见性 |
| 光圈 / 焦点 | f/0.5、f/1.4，焦点 2 档（B2-low 沿用 5.3 m、8.4 m；B2-high 按新构图设定）；另补测 f/2.8 的采样收敛 |
| 全部输入帧 | 针孔图、逐帧深度、物体 ID、前景 alpha、稳定表面 ID 与可见性（可恢复性 GT 需要知道"其他输入帧里是否露出过"，成本低） |
| 隐藏层 | 遮挡物相机射线不可见的渲染，用作隐藏层的几何与外观参考 |
| 可见性 GT | 中心视角 / 子光圈视角的表面可见性；CPU 成本另行核算（B1 的 7 小时为全量粗估） |
| 评价 | 见下方对照组与判据框架 |

**填充函数 C_fill 的实现（2026-11-10 修订）**：仓库的 BokehMe 适配器调用官方散射渲染和神经修正，没有可以单独复用的背景延拓模块，原先"与 2.5D 基线相同的背景延拓"不足以落地。改为**固定使用 LaMa** 生成背景填充图（Dr.Bokeh 官方实现采用 LaMa，仓库的 Dr.Bokeh 适配器已含该调用）。O5、O6 使用同一张 LaMa 填充图、同一个填充掩码、同一种隐藏深度约定和同一组光圈采样；LaMa 只提供剩余未覆盖区域的颜色，不能先覆盖 O6 的隐藏高斯。记录填充掩码是否用了 GT 前景分割、填充函数是否借用了真实隐藏深度；如果用了，就属于几何 Oracle 设置，不能当作实际方法的性能。

**2.5D 对照**：

| 比较 | 研究问题 |
|---|---|
| O6 − O5 | 加入真实隐藏层是否有帮助（机制是否有效） |
| O6 − O3（BokehMe，GT 深度） | 是否优于普通 2.5D 虚化 |
| O6 − Dr.Bokeh-GT | 是否优于已有的分层补全虚化（LaMa 补背景） |
| O6 − Dr.Bokeh + GT 隐藏层（可选） | 把 LaMa 补出的背景换成真实隐藏背景喂给 Dr.Bokeh，区分优势来自"隐藏内容本身"还是"三维光圈积分"；适配器支持传入背景层时做 |
| O6-GT-all − O6-GT-rec | 其他输入帧从没观察到的表面还带来多少质量差异 |

Dr.Bokeh-GT 输入同一份 GT 深度和 GT 前景 alpha，记为 **Oracle-input Dr.Bokeh**，与将来正常推理的 Dr.Bokeh 分开，不混用。若 O6 只赢 BokehMe、没赢 Dr.Bokeh-GT，优势可能来自一般性的背景补全，不一定需要动态高斯。

**判据框架**（在 Blender 评价前冻结；数值为候选）：

| 层次 | 主判断 | 口径 |
|---|---|---|
| 机制是否有效 | O6 − O5 | 相同外观、几何与合成条件下，加隐藏层的边际收益 |
| 是否有方法价值 | O6 对 O3 与 Dr.Bokeh-GT | 至少要和强分层 2.5D 基线比较 |
| 是否稳定 | 多时刻、多焦点、多光圈 | 主要组合至少约 75% 同向；低 CoC 组合单列 |
| 是否值得继续 | 区域合并 PSNR、patch LPIPS、全图护栏 | 不凭单一指标作最终判断 |

数值：合并 PSNR 保留探索性的 0.5 dB；"patch LPIPS 明显下降"候选为 **ΔLPIPS ≤ −0.01**，正式值结合固定 patch、LPIPS 版本和重复渲染噪声确定，不能看了 O6 的结果再调。即使 O6 在真实隐藏层下表现良好，也只证明这类隐藏信息在物理渲染中有价值；实际前馈网络能否从其他 12 帧恢复这些表面，是下一阶段的独立问题。

B1 实际在 4090 D 上用 OptiX 渲染；B2 若与 A2b 同时使用 GPU，需要错开时间或在记录中写明。

**MoVieS 诊断线**（与 Oracle 实验并行）：

0. **来源编号顺序**：`route3_c1_movies_cache.py`、`route3_movies_smoke.py` 用 `repeat_interleave(size*size)` 生成来源编号，默认渲染器输出的高斯 `pc.xyz` 与 `motion_opacity[0].permute(0,2,3,1).reshape(-1)` 的展平顺序一致（帧优先），代码只断言了长度。若顺序不一致，M1-cur 实际是随机的 1/13 高斯，足以解释约 9 dB；但 A1 观察到 M1-cur 的箱体是闭合的，说明大概率没有完全打乱。检查：MoVieS splatter head 有 RGB 直连通路，标为来源 k 的高斯颜色应接近第 k 帧对应像素的颜色，逐个比较即可。
1. **原生与导出一致性**：同一组高斯，比较 MoVieS 官方渲染器与项目光圈渲染器（K=1）的针孔 RGB 与 alpha，排除导出、颜色空间、相机和透明度问题。
2. **不透明度分布**：比较基础 `opacity` 与查询时刻 `motion_opacity`，统计各来源的激活值、剪枝比例和单来源 alpha 覆盖率。若当前来源整体不透明度偏低、需要多层叠加才能覆盖，约 9 dB 就是模型特性，按来源删除高斯的思路不成立。
3. **单来源测试**：在 MoVieS 官方示例和 Blender 手持视频上，分别测试单来源与全部来源的 RGB 与 alpha，判断是架构特性还是数据域问题。
4. **运动验证**：在已知运动物体上（Blender 有真值）检查预测位移、跨时刻对应与渲染误差，而不只看动态高斯比例。

**B2 结论边界**：只有 B2-low、B2-high 两个程序化场景、3–5 个代表帧，即使 75% 的组合都有提升，也只说明该受控场景中可行，不代表跨场景泛化；若决定继续训练，还需更多独立场景验证。

**B2 结论（`61dbce2`，按冻结判据，不事后修改）**：

**解读**：

1. **事实**：在可恢复区域里，真实隐藏层带来 1.9–6.2 dB 的 PSNR 提升，比 BokehMe 高 1.1–4.4 dB，每组同向。在这个受控场景中，"光圈需要的隐藏内容是 2.5D 的瓶颈"得到支持（PSNR 意义上）。
2. **待验证解释（不是已定位的原因）**：B2-low 低 CoC 组合中，O5 全图比 O3 低约 5.5 dB，提示存在与隐藏层无关的外观差距，但尚不能确定来自高斯重投影、alpha、颜色、遮挡或光学合成。L0 首先用光圈半径为 0、K=1 的针孔重渲染与原始针孔 RGB 直接比较，再逐项排查，不能先用增加 K 掩盖问题。
3. **判据设计缺陷（记录，不改结论）**：这些区域 O3 的 patch LPIPS 只有 0.004–0.009，"ΔLPIPS ≤ −0.01"在数值上几乎不可达。下一轮改为相对于基线量级的门槛。
4. **Oracle-input Dr.Bokeh 不可信**：它在焦内区比我们低 3–12 dB，而焦内区本应接近输入。记录显示存在 4.6 万个"未知天空"像素被设为 10,000 m 深度，可能是原因之一；颜色空间、CoC 映射和分辨率也需要核对。修好并通过"焦内接近输入"检查之前，不作为证据。
5. **可恢复内容几乎全部来自相机视差**：主组合中，必须靠物体运动才能恢复的像素只有 42–894 个，靠视差就够的有 8,516–17,750 个；O6-GT-all 与 O6-GT-rec 相差 ≤ 0.04 dB。第一版隐藏层可以主要依靠多帧静态几何，动态部分留到后面。
6. **MoVieS（C3 / C4）**：官方示例上单来源 alpha 同样偏低（0.20–0.47），属于模型特性；运动球区域当前来源 alpha 很高（0.92–0.96），低 alpha 主要出现在多帧共享的静态部分。运动估计偏弱（动态位移误差 0.04–0.3 m）。M2 不推进的判断不变。

**下一轮思路（用户决定先试，名称暂不确定）**：双层高斯表征。

- **第 1 部分：逐高斯解析散景**。每个高斯投影到屏幕后，按它到焦平面的距离（焦点场 F(x)）算出 CoC，直接在 2D 协方差上做解析膨胀；可以与少量子光圈（如 K = 4）结合。
  - **已知冲突**：DOF-GS、CoCoGaussian 已用逐高斯 CoC 渲染景深（静态场景、逐场景优化）。我们的输入范式不同（视频、前馈），先试，效果不好再换方法。
  - **视频场景下的待验证假设**：解析核可能更快或减少光圈积分误差，但现有 `aperture_disk()` 本来就是**确定性固定采样**，不能预设解析模式更稳定。需与固定 K=16/64、逐帧随机采样诊断组同时比较 Cycles 真值、时序误差与实际耗时。
  - **已知风险**：高斯核卷积后仍是高斯，画不出边缘清晰的散景圆盘；大尺寸溅射在部分遮挡边缘可能出现排序错误和渗色；B2 场景缺少高亮点光源，光斑形状暂时测不出来。
  - **K=4 物理约束**：解析 K=1 可模拟完整 CoC；解析+K=4 必须明确把总光圈模糊分成互不重复的解析残差与有限采样贡献，不能两边都计算完整 CoC。若做不到物理一致，K=4 只作诊断，不计为正式完整光圈替代。
  - 可学习的光圈边缘渐变、猫眼效应本轮**固定不学**（Blender 薄透镜真值中不存在，无法验证），等有真实镜头数据再放开。
- **第 2 部分：光圈环带引导的局部隐藏层**。先根据焦点与光圈算出 CoC(x)；焦内和无深度跃变的平滑区只用可见层；只在深度断层附近、前景或背景的 CoC 足迹跨过断层的"去遮挡环带"内，才从其他帧取回隐藏层（第一版以相机视差为主）。环带宽度、隐藏层的位置都由光学条件决定。**第一版环带只能使用目标帧可见 GT 深度/深度边界与 CoC 构建**，不得用隐藏 GT 反向定义环带；用独立子光圈去遮挡 GT 检查召回率、误检与漏检。为支持连续调焦，区分预构建的可恢复隐藏表面缓存与当前焦点启用的环带渲染范围，避免每换焦点重建。
- **可见层的两种形式都要测**：V-G（反投影高斯 + 解析散景，即第 1 部分）与 V-P（输入像素直接做 2.5D 散射，尽量避免高斯重建的额外外观损失）。V-P 作为诊断对照，用来判断外观损失有多少来自高斯表示本身；若 V-G 的下限无法改善，就改用 V-P 作为可见层。**实现上先做 V-G+隐藏 GS**，V-P 先单独用于诊断外观保持：2.5D 散射没有天然逐子光圈深度、alpha、透射率接口，不能把输出与 GS 直接相加。只有接口通过遮挡顺序、颜色能量和边缘接缝检查后，才纳入正式双层结果。
- 过程中遇到问题，再针对性地设计或改进模块。

**由此确定的选择**：

1. 渲染采用 K 子光圈物理积分，不采用逐高斯解析模糊；
2. 可见层采用学习式几何 + 像素锚定；边缘需要显式分离前景色与背景色，简单地在边缘不做锚定会使焦内下降 3–4 dB；
3. 隐藏层必须与可见层共用同一套几何；规则检索是当前瓶颈，学习式聚合是训练重点；
4. 评测一律使用校准后的深度与按目标对焦，主要基线为校准后的 BokehMe（DA3 深度）；
5. 真实视频的位姿可靠性尚未解决。

### 5.2 训练数据

**主方案（2026-11-11，规模待数据管线试点实测后确定）**：沿用 5.4 的 Blender 管线，批量生成程序化多场景，包括手持相机轨迹、运动物体和多层遮挡。每段提供全清晰输入帧、深度与位姿、两次剥离的被遮挡层真值、跨帧可恢复性真值，以及多焦点 / 多光圈的 Cycles 景深真值（线性 EXR）。主要风险是场景多样性（纹理、几何、光照、高光）和合成到真实的迁移；先做小批量试点，实测单场景耗时、磁盘占用与采样数后再定规模。真实视频只用于自监督微调和评测。训练数据的最终方案仍需与导师确认。

**第一批数据：只做静态场景 + 运动相机（2026-11-12，用户确认）**。第一版的核心问题是"当前视角被遮挡的静态背景能否从其他时刻的真实观测中恢复"，静态场景足以研究；运动前景放到第二批（S3-lite）。

- **相机轨迹必须有平移视差**：以横向、斜向平移和轻微前后移动为主，辅以旋转模拟手持；只转不移几乎不会显露近处遮挡物后方的内容。
- **场景按遮挡结构区分，而不是堆数量**：细结构遮挡（栏杆、椅背、枝叶）、大面积遮挡（前景后有完整墙面）、多层深度、复杂纹理与相似颜色。每个目标帧都要同时包含"其他输入帧看得到的被遮挡背景"和"所有输入帧都没看到的背景"，后者不计入真实恢复。
- **纹理规则（2026-11-13，诊断确认纹理为主因后执行，见附八）**：第三版生成器用 Generated 坐标，纹理按物体包围盒归一化，物体越小纹理越细；按其参数粗算，前景细杆上的纹理周期约 0.1–1.6 像素、面板约 1–9 像素，又是近黑对亮色的硬边，输入图在渲染时已混叠，子光圈重采样无法还原，焦内 PSNR 因此只有 13–22 dB（低纹理的 121305 为 41–46 dB）。修订为：按真实尺寸定义纹理坐标（Object 坐标，频率按每米周期数给定）；最细周期在最近观察距离下不小于 8 像素，即周期 ≥ 8 × 距离 / 711 米（约 1.3 m 处 ≥ 1.5 cm，约 5 m 处 ≥ 5.6 cm）；该式只适用于正对相机的表面，地面与斜放物体在远处和掠射角下仍会被透视压缩到亚像素，因此以逐像素投影周期（由世界坐标 pass 与材质频率计算）判定：在有效表面像素上取低分位数（初值第 1 百分位）≥ 8 像素，掠射区（视线与表面法线夹角大于约 75°）单独统计、不进入该门槛，避免极少数投影退化像素淘汰整张图；地面单独用低频纹理或随距离降低对比度；硬边改为柔边或 1/f 频谱噪声，对比度不固定在最大；前景用中等频率；每个场景记录纹理类别、最细周期（像素）、是否含高光，作为分组报告的元数据。
- **筛选原则（2026-11-13）**：正式数据只用 Blender 真值侧、与方法无关的数据有效性检查筛场景：纹理投影周期（逐像素投影周期图，有效表面低分位数 ≥ 8 像素，掠射区单列，见上条）、混叠程度（亚像素检验：保持相机光心与姿态不变，用主点偏移模拟 0.5 像素采样相位变化重渲一帧，与原图经 Lanczos 平移 0.5 像素的结果比较；只在同一表面内部、排除遮挡边界统计，并以独立种子噪声为参照。不用"1024 渲染降采样对 512 渲染"：BOX 滤波下二者都是像素面积积分，近似相同）、渲染收敛性（独立种子噪声）。A-color 零光圈重建、焦内 PSNR 与 GT-rec 收益都依赖本方法的可见层，只作诊断与分析标签分组报告，不作入选门槛，以免滤掉 SHARP 表现差的真实困难场景、按方法表现挑选测试集。留出场景按遮挡类型分层预先指定（细结构 / 大面积 / 多层各 1 个 + 随机 1 个），不按收益挑选。
- **可恢复区域按实际输入配置计算**：5 帧上下文的样本只能用这 5 帧可观测到的背景作为恢复监督，不能沿用 13 帧条件下的可恢复区域。
- **划分按独立场景或资产组合**：同一个 .blend 换几条相机轨迹，不算独立的训练集与测试集。
- **规模**：管线试点先做 2 个场景测成本与字段，确认后扩到 3–5 个；第一批训练十几个到数十个场景，依实测成本与留出表现扩展；留出至少 3–4 个独立场景起步。十几个场景只够初期开发，不足以支撑强的跨场景泛化结论。
- **数据分三级**：
  - 训练必需：全清晰针孔 RGB、内参、GT 位姿（统一坐标约定）、GT 可见深度、估计深度与校准深度、剥离隐藏层真值（位置、深度、颜色）、按输入配置计算的可恢复性、表面对应（物体 ID、物体局部坐标、世界坐标）；
  - 第一版评价：代表帧的多焦点固定景深真值（1–2 档主光圈，线性 EXR，采样充分收敛）、每场景一小段 6–8 帧连续输出、部分场景 1 条推焦曲线、PNG / MP4 预览；子光圈可见性由我们的渲染器用 GT 几何计算，不需要 Blender 渲染；
  - 第二版预留：脚本先支持字段输出，**只在 2 个试点场景上验证能正确输出**，其余场景先不渲染（见下文"另预留"）；
  - 新增（训练必需）：目标帧在一组焦点下的 K 条子光圈光线击中表面（先 K=16，导出网格 + trimesh 射线求交，焦点取法见 2.5），用于按子光圈光线定义隐藏层标签（2.5）。
- **估计位姿**只对评价子集和 E2′ 计算，不作为每个训练场景的必需项：第一版训练沿用 E1 方式（GT 位姿 + 估计深度校准）。
- **只渲染一套 512 主数据**，训练侧派生 256 / 5 帧配置；预先缓存 SHARP 可见 GS、几何估计与静态记忆，避免每个 batch 重复运行冻结模型。
- **结论边界**：第一批的 T-B / T-C 只能说明相机运动下的几何与调焦稳定性，不代表动态人物边缘、记忆不被运动物体污染等结论，这些需要第二批数据。

原"第一批最小数据集（2026-11-11）"的字段要求保留如下：按场景划分训练 / 留出（暂定十几个训练场景 + 3–4 个留出场景，依试点实测调整）。每个样本包含：13 帧输入与位姿；估计深度及校准深度；两次剥离的隐藏层真值（颜色、深度）；可恢复性、候选正确性与子光圈可见性标签；少量帧的多焦点 Cycles 景深真值（线性 EXR）；每帧第一次击中点的世界坐标 pass（用于同表面判定与记忆质量统计，见 2.3.1）。另预留（2026-11-12，见 2.3.2–2.3.3）：每场景 6–8 帧连续帧景深真值（以非输入帧为主）与 1 段推焦片段（真值按同一焦点曲线渲染）；物体 ID 与物体局部坐标 AOV；针孔 Cryptomatte；前景单独渲染（只关背景的相机可见性）与剥离背景（只关前景的相机可见性，阴影与反射保持可见）；显式设定并记录 Blender 版本、像素滤波类型与宽度（B2 脚本目前用默认值）；试点时做一次 I ≈ αF + (1 − α)B 重建检验并记录误差分布。B2-high 不进入训练，保留为固定开发评测场景。遮挡物插入增强（在真实视频中插入带 alpha 与深度的前景，原像素作隐藏真值）与真实视频跨帧留出自监督作为后续数据来源，第一版不做。

### 5.4 Blender 正式评测场景协议（B 线，2026-11-10）

**设备分工**（避免 Blender 批量渲染占用 C1 的显存）：

| 任务 | 设备 |
|---|---|
| 场景搭建、相机轨迹、预览 | 本地电脑 |
| 少量正式渲染测试 | 本地 GPU 或单独的渲染机器 |
| 全量 Cycles 真值渲染 | 按实测性能选择独立设备；不预设本地 CPU 够用，f/0.5、大面积虚化、高采样时 CPU 可能很慢 |
| MoVieS、M2、C1 | 现有 RTX 4090 D 服务器 |

**Cycles 初版配置**（经 B1 的性能与收敛测试后再锁定）：

| 配置项 | 设置 |
|---|---|
| 渲染器 | Blender Cycles |
| 分辨率 | 512×512（先与 CamVFX-4D 一致） |
| 全清晰输入 | 针孔相机，或经过验证的近似针孔配置 |
| 景深 | 开启 Depth of Field，使用物理镜头参数 |
| 光圈 | 50 mm 下 f/1.4、f/2.8、f/5.6，外加 f/0.5（与 CamVFX-4D 可比） |
| 焦点 | 近 / 中 / 远中先选 2 档 |
| 运动模糊 | 第一版关闭，避免与离焦混淆 |
| 降噪 | 正式真值默认关闭（降噪会改变高光散景、半透明边缘和弱纹理） |
| 颜色输出 | 线性 RGB EXR，另导出 PNG 预览 |
| 几何与辅助输出 | 逐帧深度、物体 ID、相机内外参 |

**采样收敛检查**：选包含明显前景边缘、高光和大光斑的代表帧，比较 128 / 256 / 512 / 1024 采样下的线性 RGB 误差、边界误差和光斑稳定性；1024 仍未收敛就继续提高。不同光圈可以使用不同采样数，但每一档都要达到可接受的收敛误差，不能因为 f/0.5 计算贵就接受明显更嘈杂的真值。

**规模先核算**：60 帧 × 4 档光圈 × 2 档焦点 = 480 张景深真值，另加 60 张全清晰图（不含深度、ID 等辅助输出）。先用 2–4 个代表帧、2 档光圈、2 档焦点在目标设备上实测单帧耗时 T_j，再按 T_total ≈ Σ_j N_j·T_j 估算，并计入写盘、场景加载和辅助通道的成本。结果和缓存放在空间充足的数据盘，不用系统盘。

**额外输出的关键真值**：Blender 有每个时刻的真实几何和相机，可以从中心相机和光圈子视角发射射线、追踪具体表面，判断该表面：
- 在中心相机是否可见；
- 在某个光圈采样视角是否可见；
- 在指定的其他输入帧中是否出现过。

由此得到**光圈去遮挡 GT** 与**跨帧可恢复性 GT**，把 C1 的近似掩码换成有真实几何依据的掩码，并用来核对时间中值背景板的误检率。运动物体需要稳定的表面标识或世界空间对应关系来追踪可见性，不能只凭物体 ID 认定是同一表面点。这比增加场景数量更有价值。

**素材**：记录来源与许可；版权不明时先汇报。

## 附十一：未观测高斯重新上色诊断执行提示词（2026-11-13，训练前最后一次诊断）

> 背景：附十 3×4 对照（`3d7686b`）中，两个 G2 试点远焦可恢复区 H(R0 / R1 / R2) 为 −0.035 / −0.430 / −0.244 dB，方法侧 M 为 +0.011 / −0.687 / −0.199 dB；近焦 R2 有部分改善（H +0.655、M +0.768 dB，不稳定）；B2-high 的 H 为 +2.70 / +3.24 / +3.15 dB。对齐支持覆盖约 96%；对齐后剩余挡光约 86% 位于参考面前方 ≤ 5% 深度。护栏：加入对齐 GT-rec 后零光圈中位下降约 3.7 dB（最差约 25 dB）；只抑制第二层不补时零光圈中位下降约 14.6 dB、焦内约 0.8–1.7 dB；只抑制未观测高斯中位约 1.9 dB。即在同一表面附近"加一层、删一层"会造成近似随机的前后次序，并伤及可见成像。
