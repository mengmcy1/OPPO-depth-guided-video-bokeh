### 1.2 本项目已有的证据（第一轮复现，静态场景）

DoF-NeRF R1（真实镜头 f/4 照片作真值）的分区结果中，四种方法的边界区 PSNR 都比焦内区低约 6 dB：CoCoGaussian 27.1 / 33.3，DoF-Gaussian 26.5 / 33.0，BokehMe 组合基线 25.4 / 31.3，DOF-GS 25.0 / 31.5（各方法完成的场景集合不同，只看量级）。来源：[`round1-regional-R1.csv`](../03_实验记录/records/dof-gs-repro-2026-11-05-round1-regional-R1.csv)。

能得出的判断：误差集中在遮挡边界；全图上 2.5D 后处理与各方法自带的景深渲染只差约 1 dB，所以"三维表示天然更好"不能当前提。局限：只有静态场景、f/4、前景/背景两档焦点，也分不清边界误差来自遮挡还是来自深度不准。

## 2. 整体方案

### 2.1 一句话主张（待验证）

从单目全清晰视频出发，**前馈**预测多帧融合的动态高斯，经**可微物理光圈渲染**生成虚化，并用虚化损失端到端训练。设计重点是"光圈能看到、而当前帧看不到"的内容：多帧能取回的部分就取回，取不回的部分显式标出（当前阶段用覆盖度 O_coverage 近似，见 2.3），再交给修复网络处理。

### 2.2 方案选择

| | 方案一（主线） | 方案二（上界 / 退路） | 方案三（扩展） |
|---|---|---|---|
| 形式 | 前馈多帧高斯 + 可微光圈渲染 + 覆盖度门控修复，端到端虚化训练 | 逐视频优化（MoSca / Shape of Motion）+ 来源分解 + 补全 | 方案一结果作初始化，再做少步逐视频细化 |
| 定位 | 论文主体 | 实验中的慢速上界；C1 失败时的退路 | 消融或"测试时细化"模式 |

三个方案共用光圈渲染器、O 和评测代码。

### 2.3 流程

```text
目标帧 I_t + 上下文帧 {I_t±2, ±4, ±8, …}（可加长时关键帧）
 ① 重建骨干：MoVieS（代码与权重开源，MIT）。需要带位姿的输入；单次最多 13 帧、长边 518；
    输出场景尺度经过归一化，渲染景深前须对齐到真实尺度
 ② 每像素高斯：位置偏移、尺度、旋转、不透明度、颜色 + 动态概率 m + 来源帧 t_ref
 ③ 融合：静态背景跨全部帧持久保留（不做不透明度衰减）；
         动态前景 v1 只取近邻帧；
         可见性过滤：上下文高斯落在当前帧可见表面前方时剔除（防鬼影）
 ④ 可微光圈渲染：光圈盘上 K 个子相机、离轴投影保持焦平面对齐，渲染后在线性 RGB 中平均；
         焦点场 F(x)、光圈 A 可控 → 虚化图 B，以及来源分解 s_cur / s_other / s_hole
 ⑤ 门控修复：输入 B、s_hole（及以后的置信度）、全清晰帧、CoC 图；
         s_hole 高处修补，覆盖充分处约束输出接近 B
```

**来源分解与覆盖度（2026-11-10 定义）**：对每个像素，在 K 个光圈样本上对高斯的 alpha 合成贡献取平均，统计三个量：

- s_cur：来源为当前帧（t_ref = t）的高斯贡献；
- s_other：来源为其他帧的高斯贡献；
- s_hole：未被高斯覆盖的比例，s_cur + s_other + s_hole ≈ 1。

O_coverage = 1 − s_hole，表示**渲染覆盖度**，不是真实的可观测度：位置错误但不透明的高斯同样会被算作"覆盖"。s_other 高只说明其他帧的高斯参与了渲染，是否正确恢复了被挡住的背景，要看去遮挡带的质量。以后加入几何一致性、跨帧重投影误差等置信度后，再定义真正的光圈可观测度。早期把"其他帧命中 + 空洞"合成一个 O 的定义作废；渲染器接口中保留的旧字段只用于兼容。

StreamSplat 使用正交投影，不能直接做光圈采样，因此不作为骨干。

### 2.4 贡献点与对应消融（均为假设）

| 贡献 | 消融（每次只改一个因素） | 主要看的区域 |

| 阶段 | 训练对象 | 监督 |

## 4. C1：前提验证（不训练）

按 AGENTS 2.4 说明：

- **要回答的问题**（按顺序）：
  1. 是否存在可恢复的隐藏背景？理想几何下，三维渲染相对 2.5D 能带来多少提升，按区域分别看（Oracle-R）？
  2. MoVieS 的多帧输出里是否已经包含这些背景？如果包含，原生聚合为什么没能正确利用（重影诊断，M1-cur 对 M1）？
  3. 我们的融合能否比原生聚合更好，同时不破坏焦内区域和时序一致性（M2a / M2b / M2c，对照 M1、M1-long）？
- **数据**：CamVFX-4D，每个视角当作一段单目输入（MoVieS 单次 ≤13 帧，按 DyCheck 做法抽帧或分段推理）。P1 已确认：每场景只有一组景深参数（f/0.5），所有视角机位固定，没有逐帧深度、掩码和 .blend，只有一份时间未知的静态网格。因此本数据只能检验**固定机位下运动物体造成的遮挡**：静态前景挡住的静态背景在任何其他帧里同样被挡，不可能靠多帧取回，只能靠补全。另外，CamVFX-4D 的光圈半径为 3.5–5 cm（35 / 50 mm 镜头、f/0.5），远大于常见设置（如 50 mm f/1.8 约 1.4 cm），属于极端条件。相机运动、多焦点 / 多光圈、常见光圈都要靠 5.1 的 Blender 正式评测补齐，正式结论不能只依赖 CamVFX-4D。
- **对照**：除 M1-long、M2c 外，各组都来自**同一次 MoVieS 前向推理**，只改变渲染时纳入哪些高斯；所有组使用同一个光圈渲染器，深度先对齐到数据集尺度。

| 编号 | 方法 | 作用 |
|---|---|---|
| M0 | MoVieS 当前帧深度 + BokehMe | 2.5D 基线（几何来源与其余组一致） |
| M1-cur | 只保留当前帧来源的高斯 | **当前来源消融**。这些高斯已经过跨帧注意力，用到了其他帧信息，不是单帧重建基线；论文中须明确区分 |
| M1 | MoVieS 原生：所有输入帧的高斯形变到当前时刻 | 4D-GRT 单目方案，直接基线 |
| M2a | M1 + 静 / 动态来源筛选：静态高斯取全部来源帧，动态高斯只取近邻帧 | 筛选本身的作用 |
| M2b | M2a + 可见性过滤 | 过滤的作用（同时检查有没有误删正确内容） |
| M1-long | 跨多次推理覆盖长窗口，各次原生高斯直接合并，不筛选、不过滤 | M2c 的同预算对照：输入帧数、推理次数、时序条件与 M2c 相同 |
| M2c | M2b + 跨多次推理的长窗口融合 | 和 M1-long 对比，才能区分"看到更多帧"与"融合设计" |
| Oracle-full | 网格初始化的高斯，完整几何，在网格对应时刻渲染 | 潜力探针（不称严格上界） |
| Oracle-2.5D | 同一份网格深度（中心视角）+ 全清晰针孔图，交给 2.5D 方法（即 M0 换成理想深度） | Oracle 的对照组。**收益 = Oracle-full − Oracle-2.5D**，按区域分别计算 |
| Oracle-clip | 裁剪掉当前视角不可见部分的几何，光圈光线打到空洞 | 只作诊断，不用来计算收益：真实 2.5D 方法会做背景延拓，不会留洞。须写明空洞的合成颜色 |
| M3 | 多视角优化参考（每时刻 50 视角重建） | 参考上界，不称 GT；先在 box、plant 各 2–3 个时刻试点，用留出视角评价，确认明显优于 M1 后再扩展 |

- **实现与运行方式**：M2 的各机制做成独立开关，在一次执行里跑完全部组合，不按阶段逐个评审。开发时用累加式（M1 → M2a → M2b → M2c）定位问题；论文消融表用逐项去掉式（完整 M2 分别去掉一项），避免结论依赖添加顺序。
- **静 / 动态划分**：不能只看单个查询时刻的位移。MoVieS 的位移是"来源时刻 → 查询时刻"，运动物体上的点在来源帧与查询时刻位置相近时位移也会接近 0。应在多个查询时刻上比较同一高斯的位移变化，变化超过阈值即判为动态。
- **区域划分（11-10 二次修订）**：所有掩码必须独立于被测方法得到，不能用 MoVieS 的输出推导。固定机位使这件事很便宜：
  - **背景板**：每个视角对 50 帧针孔图逐像素取时间中值（线性 RGB）。像素在足够多帧中都与背景板一致时，标为"背景板有效"。
  - **运动物体掩码 M_t**：每帧与背景板的差异超过阈值的像素，再做形态学清理。运动物体的阴影、反射也会被包含进来，要单独记录。
  - **光圈足迹半径**：静态部分的深度用网格（静态部分对任何时刻都成立）；运动物体深度未知，按场景最近深度取保守的最大 CoC 半径。
  - 去遮挡带拆成三类，分别报告：
    - **动态可取回带**：光圈足迹与 M_t 的边界相交（物体内外两侧都算），且足迹内被物体挡住的背景在背景板中有效。**C1 判据只作用于这一类。**
    - **动态不可取回带**：足迹条件相同，但背景板无效（物体移动幅度太小，背后的背景从没露出来过）。
    - **静-静带**：网格加光圈求交得到的去遮挡像素（P1 接口），扣除运动物体足迹附近的部分。这类内容多帧取不回，留给补全模块（C-3）；本轮只检查 M2 有没有把它弄坏。
  - **背景板顺带有两个用途**：① 它就是可取回内容的真值。把 MoVieS 的静态来源高斯渲染成针孔图，在 M_t 内与背景板比较，可以直接回答问题 2；② 把 MoVieS 判为动态的高斯投影出来，与 M_t 计算 IoU，可以检查动静划分准不准。
  - **局限**：物体运动幅度小、或长时间静止的场景，背景板不干净，要标记出来并单独报告。网格只用于静态部分；它的运动物体部分只在对应时刻有效。M3 试点通过后，可改用多视角重建推导的近似掩码（称"M3 推导掩码"，不称 GT）。
- **指标**：全图、边界区、焦内、焦外，以及三类去遮挡带的 PSNR / SSIM / LPIPS；跨帧闪烁；同时记录 s_cur / s_other / s_hole 在各类去遮挡带内的分布，作为机制分析（不作为成功指标）。动态可取回带占比过小的场景（P1 的 box 仅约 0.68%，还未区分类别）以及背景板被标记的场景，单独报告，不并入平均。
- **必报项（不设门槛）**：M1 对 M0、M0 对输入针孔图在焦内区的差距。它衡量三维渲染相对 2.5D 在焦内损失了多少，决定以后焦内是否直接取输入像素（例如按 CoC 加权混合输入与渲染，作为候选设计记录，本轮不实现）。
- **判据**：**在区域划分和 Oracle-R 完成之后、执行 M2 之前**写进 records，执行后不改。建议形式如下，需用户确认：
  - 记 G 为动态可取回带内 Oracle-full − Oracle-2.5D 的场景平均 PSNR 差值。若 G < 0.3 dB，说明本数据无法区分融合效果，停止对 M2 下结论，转由 Blender 场景检验；
  - 主指标：动态可取回带的 PSNR 与 LPIPS。M2b 相对 M1、M2c 相对 M1-long，在有效场景上的平均 PSNR 提升 ≥ min(0.5 dB, 0.3·G)，同时 LPIPS 下降，并且至少约 70% 的有效场景同向；门槛不得超过 G；
  - 护栏：焦内区、全图、静-静带的 PSNR 相对 M1 下降不超过 0.2 dB，跨帧闪烁不变差；
  - 达标就进入训练阶段。不达标时，先根据 Oracle-R 与重影诊断判断是"没有可恢复内容"、"MoVieS 没重建出来"还是"融合方式不对"，查清之前不开始训练。
- **结论边界**：合成室内场景、512²、单一且极端的景深参数（f/0.5，光圈半径 3.5–5 cm）、固定机位、只针对运动物体造成的遮挡，结论只适用于这一条件。
