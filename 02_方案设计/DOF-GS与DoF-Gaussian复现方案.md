## 1. 目的与边界

本次复现有两个目的：

1. 弄清 3DGS 景深渲染的机制、质量与成本，为 3DGS 虚化路线提供第一手证据；
2. 为后续“三维表示 + 光学虚化”方法准备对照组，尤其是“在三维中做虚化”与“在二维结果上做后处理虚化”的对比。

两篇都是**静态场景、逐场景优化**的方法：输入同一场景的多视角离焦照片（Deblur-NeRF 数据集），每个场景单独训练一套高斯，训练后可渲染全清晰图并任意改焦点和光圈。它们与 2026-09-30 汇报中的视频虚化基线任务不同：

- 质量指标不与 PPT 中 Any-to-Bokeh 等方法放进同一张表；FVD、FD、RM、VEPI 等视频指标不适用。
- 效率可以并列展示，但必须注明 3DGS 方法需要先逐场景训练。

结论边界：这是在声明条件下复现官方实现。DOF-GS 作者说明原始 checkpoint 已在服务器迁移中丢失，公开的是重训结果。与论文有差距时如实报告，不调参凑数；每个场景训练一次，差距很小时不判定优劣。

## 3. 数据与划分

- **Deblur-NeRF 真实离焦 10 场景、合成离焦 5 场景**。两个仓库各自提供 Google Drive 数据包：DOF-GS 的包含合成场景的 COLMAP 结果；DoF-Gaussian 需要用作者修改版 COLMAP 生成稀疏深度。
- **测试视角**：每隔 8 张取 1 张（llffhold=8），按场景划分，不跨场景混用。开始前核对两个仓库选出的是同一批文件，并核对测试分辨率（DOF-GS 为 600×400，DoF-Gaussian 为 `-r 4`）。
- **数据包差异**：两个仓库的数据包与 COLMAP 结果可能不同。主表各用官方默认流程，差异写入记录；E1 统一协议时，以同一份图像和测试列表为准。
- 原始数据只读；需要写入 COLMAP 中间结果的流程使用副本（见第 7 节）。

## 4. 对比方法

| 方法 | 级别 | 用途 |
|---|---|---|
| DOF-GS（CVPR 2025） | 必做 | 复现对象；逐高斯离焦，训练 40k 步 |
| DoF-Gaussian（CVPR 2025） | 必做 | 复现对象；渲染后逐像素散射，训练 30k 步，含逐场景深度先验 |
| Mip-Splatting（CVPR 2024） | 必做 | 不建模镜头的下界；DoF-Gaussian 的基础代码；E4 的全清晰渲染速度基准 |
| 3DGS 渲染 + 2.5D 后处理虚化 | 建议 | 用同一套高斯渲染全清晰图和深度图，再交给项目已复现的 BokehMe、MPIB、Dr.Bokeh 做虚化，与两篇自带的离焦渲染对比，回答“三维中做虚化是否优于二维后处理”，重点看遮挡边界。沿用项目已有的这几个方法的环境与适配代码 |
| CoCoGaussian（CVPR 2025） | 建议 | 同类方法：学习光圈参数，每个离焦圆生成多个高斯拟合圆斑形状，思路最接近光圈内采样。先核实是否支持训练后换焦点渲染；不支持则只比较全清晰质量和效率 |
| BAGS、Deblurring 3DGS（ECCV 2024） | 后续 | 全清晰指标最强的去模糊方法，但不能重对焦；暂时引用论文数值 |
| Cinematic Gaussians（PG 2024） | 后续 | 需要多曝光、多光圈的输入，留到做高光/HDR 时再看 |
| Dydeblur（NeurIPS 2025） | 后续 | 进入动态场景时的第一个对照 |

NeRF 类方法（Deblur-NeRF、DP-NeRF、DoF-NeRF、PDRF）引用论文数值，不运行。所有方法使用官方默认配置，不为“公平”去掉某一方的核心模块。

## 5. 指标口径

### 5.1 质量

全清晰新视角的 PSNR、SSIM、LPIPS，逐场景报告再取平均。使用统一评价脚本；官方脚本的结果一并保留，用于核对统一脚本是否有偏差。全清晰渲染：DOF-GS 设 Q=0，DoF-Gaussian 设光圈 A=0。

### 5.2 效率

计时前后做 CUDA 同步，排除模型加载与写盘；先预热，再多次重复取平均。显存同时记录 `torch.cuda.max_memory_allocated` 与 nvidia-smi 定时采样峰值，与项目已有效率测量口径一致。统一在本机 RTX 4090 D 上测量；论文中 A6000 等硬件的数值只作参照，不计算跨卡加速比。

| 指标 | 定义 |
|---|---|
| 每场景总耗时 | COLMAP + 深度先验微调（只有 DoF-Gaussian 有）+ 高斯训练，三段分别记录 |
| 训练峰值显存 | 训练全程两种口径的峰值 |
| 单张渲染时间 / FPS | 训练后在测试视角渲染，全清晰与景深分别测 |
| 渲染峰值显存 | 同上，分开记录 |
| 高斯数量、参数量、模型大小 | 最终 checkpoint 的点数；参数量 = 点数 × 59，加每视角镜头参数；DoF-Gaussian 的深度网络（mc.pth）只在训练使用，单列 |

## 6. 扩展实验

| 编号 | 内容 | 级别 | 说明与局限 |
|---|---|---|---|
| E1 | 同协议直接对比 | 必做 | 同一份图像、测试列表、分辨率和评价脚本下比较两篇；单次运行，小差距不判优劣 |
| E2 | 补全缺失指标 | 必做 | DOF-GS 补 LPIPS；两篇补齐第 5.2 节的全部效率指标 |
| E4 | 渲染成本随光圈变化 | 必做 | 固定场景和焦点，按画面最大离焦圆半径 0、2、4、8、16、32 像素对齐两篇的光圈参数（DOF-GS 的 Q 与 DoF-Gaussian 的 K_bokeh 单位不同，不按数值对齐），记录渲染时间与显存。DOF-GS 的高斯覆盖像素数、DoF-Gaussian 的散射邻域都约按半径平方增长；该曲线用于估算光圈内多视点采样渲染的成本。结论只针对这两个官方实现 |
| E5 | 质量—迭代与质量—时间曲线 | 建议 | 每 5k 步保存并评价，得到 PSNR 对迭代数、对实际耗时的曲线，以及达到同一 PSNR 的时间；两篇默认步数不同（40k 与 30k） |
| E7 | 无真值的重对焦评价 | 建议 | 三个代理指标：焦点区域内离焦图与全清晰图的 PSNR；局部模糊量与理论离焦量 \|1/z − 1/f\| 的相关系数；相邻视角按深度变换后的一致性。另按相同离焦圆半径做定性网格，重点看前景边缘的颜色外溢与光晕。只说明行为是否合理，不作物理正确性结论 |
| E3 | DoF-Gaussian 跑合成 5 场景 | 可选 | 需先确认能否复用 DOF-GS 数据包中的 COLMAP 结果 |
| E6 | 高分辨率 | 可选 | 复现 DOF-GS Table 2，并让 DoF-Gaussian 在相同分辨率下运行；选 2–3 个场景；显存不足如实记录 |
| E8a | 按 DoF-Gaussian 合成协议自建重对焦数据 | 可选 | LLFF 与 T&T 全清晰图 + DepthPro 深度 + BokehMe 渲染浅景深，计算重对焦 PSNR/SSIM/LPIPS 与 δA、δF，注明“按原协议自建”。“真值”本身是 2.5D 渲染，判断不了部分遮挡；“3DGS + BokehMe”组合基线在这套数据上存在循环偏向，不能用它评价该组合 |
| E8b | Blender 光线追踪物理真值 | 后续 | 需先确认 Deblur-NeRF 合成场景文件是否公开；唯一能评价部分遮挡的方式，也是 C4 基准的雏形 |
| E9 | 源码与论文差异的单因素检查 | 后续 | DoF-Gaussian 焦区损失实际用 1−Ψ、Eq. 11 光圈自适应未在主训练启用；在 1–2 个场景上开/关对比 |

## 7. 环境与文件放置

系统盘 `/` 只剩约 2.3G，现有 `any2bokeh`、`magicbokeh` 环境装在系统盘上，新环境与缓存一律放数据盘。两篇的 CUDA 扩展依赖不同，各用独立环境。

```text
/root/autodl-tmp/
├── DOFGS_implementation/     官方仓库，与已有 baseline 平级，不进项目 Git
├── DoF-Gaussian/
├── mip-splatting/
├── CoCoGaussian/
├── envs/
│   ├── dofgs/                Python 3.9 + torch 2.0.1 cu118 + 环境内 nvcc 11.8
│   ├── dofgaussian/          Python 3.9 + 固定的 cu121 版本 torch（系统 nvcc 12.8 可编译）
│   ├── mipsplatting/、cocogaussian/   按各自 README，能与上面共用时再合并
│   └── colmap-build/         COLMAP 编译依赖（conda-forge），只在需要编译时建
├── tools/colmap-dofgaussian/ 修改版 COLMAP，各方法共用
└── .cache/                   conda 包、pip 包、TORCH_HOME 缓存
```

项目内：原始数据 `data/raw/DeblurNeRF/`（只读，各仓库用软链接指向）；DoF-Gaussian 的 `colmap.sh` 会写入数据目录，因此使用副本 `data/processed/deblurnerf-dofgaussian/`；大产物 `outputs/dof-gs-repro-<启动日期>/<方法>/`，日志 `logs/` 同名目录；小型指标写入 `03_实验记录/records/`，前缀 `dof-gs-repro-<启动日期>`。

安装注意：

- DOF-GS 的 `environment.yml` 写死了 torchvision 0.13.1，会先装旧版 torch 再被 README 中的 2.0.1 覆盖；建环境时去掉这几行，直接装 cu118 三件套。
- DoF-Gaussian 的 README 环境命令有笔误（`conda activate -n`），且 torch 未固定版本；固定一个 cu121 版本并记录。
- DoF-Gaussian 的深度网络权重 `mc.pth` 已在仓库内，LPIPS 权重同样在仓库内。

## 8. 执行步骤与停止点

1. **准备**（不占 GPU）：克隆仓库，建环境，编译光栅化扩展；下载 Deblur-NeRF 真实与合成数据、DOF-GS 作者重训场景；确认 COLMAP 方案。
2. **单场景跑通**：defocuscake 上两篇各训练一次，与论文该场景数值对照；评价 DOF-GS 作者重训场景，核对评价脚本。**停止点**：差距明显时先排查数据、分辨率与评价口径，不直接铺开全量。
3. **主表**：真实 10 场景跑 DOF-GS、DoF-Gaussian、Mip-Splatting；合成 5 场景跑 DOF-GS；统一脚本出表（E1、E2）。
4. **效率**：按第 5.2 节测量，并完成 E4。
5. **建议项**：组合基线、CoCoGaussian、E5、E7。完成后汇总，再由用户决定可选项与后续项。

GPU 时间粗估：必做约 12–16 小时，建议项约 8–10 小时。DoF-Gaussian 每场景约 20 分钟（论文 A6000 数值），DOF-GS 40k 步每场景约半小时到一小时，以单场景实测为准。

## 9. 风险

| 风险 | 对策 |
|---|---|
| 修改版 COLMAP（B1ueber2y/colmap 分支）较老，需 CUDA 编译稠密重建，可能与 CUDA 12、新版依赖不兼容；作者也说明仓库缺文件 | 先确认作者数据包是否已含训练所需的 COLMAP 结果；不含则用 conda-forge 依赖在数据盘编译；仍失败时由用户从作者百度网盘下载其版本 |
| DOF-GS 需 nvcc 11.8，系统只有 12.8 | 在 `envs/dofgs` 内安装 cuda-nvcc 11.8；gcc 11.4 在 CUDA 11.8 支持范围内 |
| Google Drive 文件夹有下载配额 | 失败时由用户本地下载后上传 |
| DOF-GS 原始权重丢失 | 以作者重训场景和本地重训结果为准，与论文数值的差距如实报告 |
| 2400×1600 下显存接近 48GB 上限 | E6 只选少量场景，显存不足如实记录 |
