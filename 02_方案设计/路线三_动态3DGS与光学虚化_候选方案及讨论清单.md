# 路线三：动态 3DGS / 4DGS + 可控光学虚化——候选方案与论文讨论清单

> 记录日期：2026-10-29  
> **状态：读文献期间的备选研究方案与问题清单，尚未确定 Ours，未实现、未训练、未复现以下三篇的组合。**  
> 定位：与[路线一 V2 隐式几何焦点相对表示](V2候选方案-隐式几何与焦点相对表示_Stage0验证.md)及“路线二：几何/场景记忆驱动生成”并列探索；总纲见[跨方向架构调研提纲](../视频虚化生成_跨方向架构文献调研提纲.md)。  
> 讨论原则：先理解作者**真正解决的任务与前提**，再讨论可迁移机制；**不把现有论文机械拼装当作创新点**。当前仓库 V2 Stage 0 已有实测结果，路线三并未因之开始实施。

## 1. 我们想解决的任务（和现有论文的边界）

目标任务：给定普通、未必标定的**单目全清晰动态 RGB 视频**与用户指定的对焦主体或相对光学控制，生成时序一致、边界合理且可改变焦点/光圈的虚化视频；研究重点放在**场景中间表示与生成/渲染范式**，不是先限制 3GB、5秒，也不把 3DGS 只当成一个后处理滤镜。

候选路径：

~~~text
单目全清晰视频 V_t
     ↓
视频几何 / 外观 / 运动特征
     ↓
时序一致的 Gaussian 场景 G(t)（静态背景 + 动态主体？）
     ↓                          ↑
有限光圈渲染 / 可见性建模 ← 对焦主体、焦平面、相对 K、光学参数
     ↓
虚化视频 B_t
     ↳ 可选：仅在必要时用生成式补全/残差修正
~~~

与 ATB 的核心区别是：ATB 在 VAE 潜空间以几何条件直接预测 Bokeh Latent；路线三试图**维护可被不同焦点条件反复查询的三维/动态场景表示**，让虚化由光学成像与可见性计算产生。不同范式不保证效果更好；**3DGS 的几何错误同样会导致错误虚化**。

必要区分：

- **镜头移动/重对焦的静态 3DGS** ≠ **场景内人物/车辆独立运动的动态 3DGS**。
- **有可微虚化渲染器** ≠ **能够由普通单目视频可靠重建 Gaussian 场景**。
- **输入没有显式深度图** ≠ **没有学习到/依赖几何估计**。
- **三维重建可渲染清晰图像** ≠ **在遮挡边界可以渲染真实光学散景**。
- **深度、CoC 的误差**可能变为 Gaussian 位置、半透明混合、运动变形或相机参数误差，不会自动消失。

## 2. 三篇核心论文：读什么、不能直接借什么

### P1. StreamSplat（优先：动态场景从哪里来？）

**Zike Wu 等，ICLR 2026，*StreamSplat: Towards Online Dynamic 3D Reconstruction from Uncalibrated Video Streams*.**

- [ICLR 正式版](https://proceedings.iclr.cc/paper_files/paper/2026/hash/c822d05dcc00695ed6b63c9e97bb3449-Abstract-Conference.html) · [项目](https://streamsplat3d.github.io/) · [官方代码](https://github.com/DSL-Lab/StreamSplat) · [arXiv](https://arxiv.org/abs/2506.08862)。
- **原任务**：在线、前馈地把未标定的单目视频转成随时间变化的 Gaussian 表示，用于三维重建与新视角合成，**不负责真实镜头的有限光圈虚化**。
- **值得精读的三个机制**：概率式 Gaussian 位置预测；双向形变场（如何在帧之间关联动态 Gaussian、减少漂移）；自适应 Gaussian 融合（历史存留、新出现和消失的内容怎样处理）。重点看它们各自的输入、输出、监督和推理状态。
- **公开实现的关键前提**：官方 README 的推理示例有 `--input_depths_path`，需要 Depth Anything V2 的预计算深度，尽管论文称相机未标定、无需逐场景优化。须区分“camera-free”与“depth-free”。不能据此宣称已经解决了深度误差依赖。
- **读后待回答**：Gaussian 是每帧直接预测还是长期维护？世界坐标和相机位姿如何定义/对齐？形变场如何区分相机运动与独立物体运动？动态遮挡位置是否真实补全，还是只维护可见 Gaussians？预计算 Depth 的误差如何进入 Gaussian 预测？

**同名论文提醒**：Changhao Song 等的 [*StreamSplat: Streaming Feed-Forward 3D Gaussian Splatting*](https://arxiv.org/abs/2608.01659)（2026-08 预印本）主要研究**按顺序到达的已标定视角的增量重建**，有 VACC/HPDA/CGFI 等场景缓存机制；与上述 ICLR 动态单目论文**不是同一篇**。它对路线二的场景记忆有用，但不作为本次路线三的主要动态重建基线。

### P2. DOF-GS（优先：Gaussian 怎样变成真实的虚化？）

**Yujie Wang 等，CVPR 2025，*DOF-GS: Adjustable Depth-of-Field 3D Gaussian Splatting for Post-Capture Refocusing, Defocus Rendering and Blur Removal*.**

- [CVPR 论文](https://openaccess.thecvf.com/content/CVPR2025/html/Wang_DOF-GS_Adjustable_Depth-of-Field_3D_Gaussian_Splatting_for_Post-Capture_Refocusing_Defocus_CVPR_2025_paper.html) · [项目](https://dof-gs.github.io/)。
- **原任务**：从多视角、带适度离焦的图像重建场景，同时利用有限光圈的可微离焦渲染，实现重对焦、不同光圈以及全清晰合成。**不等于给任意动态单目视频直接做虚化**。
- **值得精读**：有限光圈是怎样积分/近似的？Gaussian 的位置、尺寸、透明度和镜头参数如何影响光学散景？光圈与焦点距离的参数化、梯度是否能回传到几何？它的 CoC/近焦 Mask 在重建训练中做什么？重建阶段对相机标定、输入多视角和优化的依赖是什么？
- **迁移边界**：作者训练用含离焦的多视角观测，我们的输入是全清晰视频；镜头标定、动态运动与遮挡错误不会因为接入渲染器自动解决。要分清“对正确的 Gaussian 场景做虚化”和“从单目视频恢复正确的 Gaussian 场景”。

补充查重：[DoF-Gaussian（CVPR 2025）](https://openaccess.thecvf.com/content/CVPR2025/html/Shen_DoF-Gaussian_Controllable_Depth-of-Field_for_3D_Gaussian_Splatting_CVPR_2025_paper.html)、Cinematic Gaussians 等也涉及可控景深；**Gaussian + 有限光圈/CoC 并非新概念**。

### P3. Dydeblur（中山大学；优先：模糊与 Gaussian 表示怎样联合优化？）

**Xuankai Zhang、Junjin Xiao、Qing Zhang，NeurIPS 2025，*Dynamic Gaussian Splatting from Defocused and Motion-blurred Monocular Videos*.**

- [NeurIPS 正式版](https://proceedings.neurips.cc/paper_files/paper/2025/hash/67159f1c0cab15dd34c76a5dd830a389-Abstract-Conference.html) · [项目](https://dydeblur.github.io/) · [官方代码](https://github.com/hhhddddddd/dydeblur)。
- **原任务方向相反**：输入已经有离焦/运动模糊的单目视频，重建更清晰的动态三维场景，进而渲染清晰新视角；**不是**“全清晰 → 用户指定的新虚化”。
- **值得精读**：像素级 Blur Prediction Network 如何结合场景/相机信息？Blur-aware Sparsity Constraint 对 Gaussian 分布有什么约束？Dynamic Gaussian Densification 如何处理场景不完整区域？渲染损失如何反馈至几何与运动？
- **迁移边界**：反求观测模糊核与正向控制目标光圈、焦点不等价；它的训练/逐场景优化机制不能直接视为前馈视频虚化。值得讨论的是：**能否反过来让“目标光学虚化”的训练监督影响 Gaussian 的几何/透明度/运动表示**，而不是单纯套用其去模糊网络。

## 3. 三种候选总体方案（供读完后共同筛选，均未冻结）

| 方案 | 核心数据流 | 研究价值 | 最大问题 |
| --- | --- | --- | --- |
| **A：现成重建 + 光学渲染基准** | RGB 视频 → 动态 3DGS（如 StreamSplat）→ 有限光圈渲染（参考 DOF-GS）→ 虚化视频 | 判断物理渲染、遮挡与跨帧是否真的优于 Depth+CoC；分离重建错误和渲染错误 | 多数是已有模块拼接，论文创新性弱；接口和坐标不一定兼容 |
| **B：面向离焦的动态 Gaussian 表示** | RGB/运动 → 具有可见性与运动状态的 Gaussian → 多焦点光学监督联合优化表示 → 渲染 | 可能在**表示学习/高斯状态更新/光学损失耦合**中形成任务专属方法 | 数据监督、遮挡可观测性、光圈误差与深度尺度歧义；需要证据证明超越普通 3DGS |
| **C：Gaussian 物理渲染 + 局部生成式补全** | 动态 Gaussian → 光学虚化 + 可见性/不确定性 → 仅针对错误或新显露区域进行补全/残差生成 | 缓解未观测背景、细发丝、半透明与高光边界；可能兼顾物理控制和外观质量 | 生成器是否真正利用 Gaussian/可见性；成本较大；与物理+神经残差先例重叠 |

### A. 实现兼容性与“最小可行性基准”

先不谈创新：选一段相机静止的静态场景和一段存在独立运动的单目视频，分别核查：

1. 预训练动态 3DGS 输出究竟是什么（Gaussian 属性、相机坐标/位姿、动态状态、可见性）；
2. 光学渲染器的输入是什么（相机内参、镜头焦距、光圈、对焦距离、Gaussian 属性等）；
3. 两边是否能够在**不改造核心表示**的情况下共享坐标、单位和深度尺度；
4. 如果采用 StreamSplat 的估深输入，几何错误是否仍直接决定错误虚化。

A 是技术可行性与问题诊断的基准，而非默认最终方法；对同一 Gaussian 场景可测试多个焦点/光圈，不必每次重建。

### B. 可能更有研究价值的整体架构

暂拟三个互斥或可先单独验证的核心假设：

- **B1：Focus-/Aperture-Aware Gaussian Optimization**：让不同焦点/光圈下的真实或可信光学监督直接约束 Gaussian 的几何、透明度、尺度和运动状态，而不是只用清晰重建损失优化场景、随后加一个 DoF 渲染器。必须证明超越 DOF-GS 已有的光学监督；新点更可能发生在**动态时序与遮挡**。
- **B2：Visibility-/Occlusion-Aware Dynamic Gaussian State**：维护动态主体与背景的分层、可见性/置信度或跨帧关联，使有限光圈渲染时前后景的贡献合理，而不是把单层 Depth 错误直接传入光学核。需要区分 Gaussian 位置错误、透明度混合误差、未观察区域缺失及真实反射/透射。若仅使用普通 alpha compositing，可能不足以解决复杂散景边界。
- **B3：Compact Optical Scene Representation**：不一定要完整世界级 4DGS；可考虑在原视频相机轨迹附近使用可跟踪的**多层/局部动态 Gaussians**表示，只学习足以支持焦点切换与遮挡处理的三维信息。必须与 MPI、TMPI、SHARP、Flash3D、DoF-Gaussian 已有分层/可渲染表示逐项比较；不能因为“更轻”就自动当作创新。

可用的**可验证差异**：同一段视频的不同焦点输出应该共享场景状态；焦点切换不能引起几何漂移；动态主体的遮挡和新显露背景不能引入明显的逐帧跳变；有限光圈效果应符合明确镜头参数或声明为相对控制。不要把这些目标未经验证地写成已有模型能力。

### C. 物理 + 神经混合生成

建议仅在 A/B 确认具体失败类型后讨论：

- 物理 Gaussians 负责**可解释的视差、可见性、遮挡顺序和基本离焦**；
- 生成分支仅处理三维表示不充分的部分，例如始终被遮挡的背景、发丝和反射/焦外高光；需要防止生成分支覆盖物理焦点控制，或重新引入不受控的几何幻觉；
- 对照至少包括“纯 Gaussian 光学渲染”“纯 RGB 条件生成”“Gaussian + 生成残差”，且训练数据、光学控制和评价口径一致。

暂不选定 C，也不提前把 ATB 的 U-Net 或 Guided Decoder 作为必需组件。

## 4. 读完三篇后需要集中讨论的八个问题

1. **表示粒度**：我们需要完整的世界坐标动态 4DGS，还是可随原视角查询的局部/分层 Gaussians 就足够？
2. **几何来源**：到底是否需要外部 Depth Anything/VDA？若估深错误，Gaussians 会怎样受影响？能否通过多帧观察降低误差，而不只是换一种存储形式？
3. **场景运动**：静态背景与动态前景如何拆分、维护、变形？镜头运动与主体运动怎样区分？如何处理新出现/消失的 Gaussians？
4. **光学成像**：有限光圈怎么处理遮挡与可见性？屏幕空间 CoC / Gaussian 核扩张与真实 aperture 积分有什么根本差异？是否支持光圈形状、焦外高光？
5. **焦点定义**：用户只点击一个像素/主体时，怎样转换成对焦平面？未知米制尺度和相机内参时，到底能承诺物理焦距还是相对虚化强度？
6. **隐藏背景与生成**：3DGS 能否恢复输入视频从未看到的区域？何时必须额外补全？真实视频多帧观察与生成先验怎样分工？
7. **训练范式和数据**：StreamSplat 是前馈预测、DOF-GS/Dydeblur 如何逐场景优化？我们究竟要训练新的通用前馈模型还是每段视频单独优化？清晰/多焦点 GT 从哪里来，如何避免错误深度伪标签？
8. **新颖性与对照**：相比“StreamSplat + DOF-GS”直接连接，以及 DoF-Gaussian、Dydeblur、MoDGS，候选方法**新增的表示机制/训练目标/可见性建模是什么**？如何用单因素实验证明它的贡献？

## 5. 建议的下一次讨论顺序（现在不执行）

**第一轮：逐篇机制对齐**。StreamSplat：输入/深度依赖/动态表示/更新状态；DOF-GS：相机模型/有限光圈积分/CoC 监督/重建前提；Dydeblur：反向模糊任务/Blur Kernel/动态增密。读论文后以正文和官方实现为准核对图表，必要时修正文档中的假设。

**第二轮：完成一个跨论文的接口表**。列出各自的场景属性、坐标与尺度、相机参数、运动、光学渲染和损失；判断哪些模块能够物理和数值一致地连接。特别标出“需要深度/位姿/多视角/预训练权重/逐场景优化”的隐性条件。

**第三轮：选定一个单一核心科学问题**。比如“复杂遮挡下的动态光学可见性”或“多焦点监督下的几何状态更新”，而不是一次做完重建、补全、时序记忆和加速。

**第四轮（待讨论后决定是否实验）**：用一个静态和一个动态视频进行输入权限一致、焦点可重复的定性/小规模定量诊断；指标包括焦点区域保真、背景虚化强度、遮挡边界、跨帧稳定性、相机运动/独立运动分组。若没有可信的配对 Bokeh GT，只能报告物理一致性诊断、人工观看和与输入/参考的相对差异，**不能把重建 PSNR 当作 Bokeh GT 质量**。

建议的初期对照矩阵（仅研究计划，不是已完成结果）：

| 方法 | 场景表示 | 生成方式 | 应判断的问题 |
| --- | --- | --- | --- |
| ATB | Depth/CoC/MPI 条件 + RGB Latent | 单步潜空间 U-Net | 原基线在遮挡/复杂边界的失败 |
| 静态 3DGS + DoF | 静态 Gaussians | 有限光圈渲染 | 静态场景能否出现明确优势 |
| 动态 StreamSplat + DoF | 动态 Gaussians（含预估深条件） | 有限光圈渲染 | 动态建模是否提供额外价值、误差是否扩散 |
| 拟议 B 或 C | 待明确的任务专属表示/补全 | 待定 | 是否存在非机械拼接的额外收益 |

## 6. 暂缓项与结论边界

- 现在**不启动代码实现、GPU 训练、模型权重下载、大规模数据处理或新 baseline 实验**；这里只保存后续讨论依据。
- 不修改原有 ATB、MagicBokeh、Synthetic/DAVIS 结果；不影响路线一已有的 V2 Stage 0 阶段结论。最新状态见[中央进度](../03_实验记录/当前实验进度与方法论.md)：V2 Stage 0 已完成，P3 对 P2+ 有增益，但仍不及直接 VGGT 最终深度 P2；**这也不证明路线三的 Gaussian 更可靠**。
- 不预先认定“3DGS 相关研究少”或“显式 3DGS 就一定比 latent 扩散优越”；已有 DOF-GS、DoF-Gaussian 和动态 Gaussian 文献必须查重。
- 下一次用户读完论文后，优先逐篇核对**论文明确成立的机制、工程条件、可迁移限制**，再选择 A/B/C 中一条验证；本文的 B1/B2/B3 都是候选研究假设。
