## 稳定问题背景

课题原文面向云端离线精修，以 OPPO 手机双目系统记录的高帧率 RGB 视频与低帧率粗糙深度为输入，目标是研究深度补全、主体及边界处理、可控虚化和时序一致性的统一视频虚化方法。

原文已提出共享时序表征、深度/alpha/虚化三个输出分支、物理渲染与神经残差结合的候选路线，并提出数据集（数据制作方案）、训练模型与代码等交付目标。原文计划为 2026 年 10—12 月完成数据准备与 baseline 搭建，2027 年 1—5 月优化方法与中期检查，2027 年 6—9 月提升效果和效率并结题。这些是提案内容，具体实现、可行性、时间安排和最终验收口径仍需确认。

### 阶段 E6：24 场景开发验证——验证 Benchmark 构造规则是否可靠

当前状态：**E6 已在声明范围内验收通过**。24 场景全流程及结构/关键帧检查已完成；小半径结论范围、开发排除清单及正式测试保留素材池的源 ID 隔离已落实。详见本节末验收记录；正式 E7 场景尚未冻结。E1–E5 已完成 Renderer 可行性验证；E6 的目标是验证正式 Benchmark 冻结前的构造协议，不能仅通过扩大样本量宣告通过。

| 组成 | 数量 | 核心目的 |
|---|---:|---|
| AM-2k 静态前景 + 受控运动 | 12 场景 | 控制变量，检查深度、遮挡、焦点及 K 的影响 |
| VideoMatte240K 动态前景 | 12 场景 | 检查真实动作、发丝、衣物边缘及 Alpha 的时间变化 |
| 独立标定画面 | 另计 | 检验不同 K、焦点和深度条件下统一映射是否成立 |

每场景延续 25 帧、1024×576。VideoMatte 提升的是时间上的真实运动；人物仍作为一个或若干二维平面进入场景，统一称为**动态分层平面合成**，不得称为真实三维人体几何。

#### 场景设计与素材隔离

- AM-2k 使用有意设计的配对场景：固定同一前景、背景及其他参数，分别只改变前景深度、背景深度、Focus 或 K；遮挡变化也需明确控制因素，不能随机凑满 12 场景。
- VideoMatte 的 12 场景覆盖头发运动、快速手臂运动、衣物边缘、姿态变化、明显 Alpha 变化及遮挡区域变化；允许一段素材覆盖多种现象，但必须记录实际覆盖情况。
- 记录源素材标识、源视频及取帧区间、变换、参数与随机种子。具体素材清单及参数组合在执行前确定，尚未选定的内容不写成已完成。
- 正式测试与 E1–E6 开发集按**源素材级别**隔离：VideoMatte 必须使用不同源视频，同一视频的不同帧段不算隔离；AM-2k 前景和 BG-20k 背景同样按原始素材隔离，裁剪或变换不能改变素材归属。

#### 统一映射与验证顺序

1. 先核对代码中 K、深度/视差的单位和归一化方式，明确焦点距离、物体深度、焦距、传感器尺寸及图像分辨率如何进入虚化尺度关系，再确定一套统一公式或统一标定规则。
2. 现有 K=16、焦点 2 m、背景 6 m、50 mm/36 mm 相机下的 f/2.10054 仅是参考标定点。固定统一规则后，用独立画面验证不同 K、焦点及前后景深度；禁止逐场景调整光圈去拟合 Dr.Bokeh。
3. 先做标定画面与短片段检查，再批量生成 24 场景。若统一规则仅在有限范围成立，明确限定 Benchmark 的有效参数区域，不为覆盖所有情况引入手工参数。
4. 以标定偏差、独立采样种子/高采样参考下的噪声和时间变化、Alpha/遮挡边缘检查为主要证据；Any-to-Bokeh 分数仅描述预测与参考的距离。24 段视频不自动构成稳定 FVD 估计的充分样本。

#### E6 通过条件与 E7 入口

以下条件均需有实际记录支持；执行前明确量化判据和检查方式，不能在看到结果后调整标准以宣告通过：

- 统一 K—相机参数映射在拟纳入正式 Benchmark 的范围内无明显系统偏差；范围外情况明确排除或保留为待解决问题。
- Blender 采样噪声不会造成明显视频闪烁，独立采样对照能区分真实运动与采样变化。
- Alpha 与遮挡边缘不存在系统性合成错误，AM-2k 与 VideoMatte 两类前景均能稳定工作。
- 固定种子、素材清单和配置可以复现构造过程；输入生成的确定性与随机路径追踪的采样稳定性分别验证。
- 正式测试集能与开发集按源素材级别隔离，并有明确的素材归属记录。

#### E6 准备与首轮标定结果（2026-09-26）

- 清单与预设判据：`configs/renderer-e6.json`。AM-2k 为 2 组 × 6 场景，每组含参考、仅前景深度、仅背景深度、仅焦点、仅 K、增加遮挡层；VideoMatte 为 12 个独立源视频候选，已登记帧区间及开发素材排除清单。素材、变换后屏幕尺寸与其他参数保持固定的配对用于隔离深度影响。
- 统一规则：视差采用 `d=1/z_m`，不按场景归一化；目标圆形弥散半径 `R_px=K*abs(1/z_m-1/Zf_m)`。对于当前 Cycles 透视相机、水平传感器匹配和方形像素，使用 `N=f_m²*W_px/(2*S_m*K)`。物距与焦距平面通过半径差值起作用，在解出 N 的系数时抵消；这是当前相机模型的关系，不是任意相机/深度归一化下的通式。依据为 [Blender 4.5.13 光圈转换](https://github.com/blender/blender/blob/v4.5.13/intern/cycles/blender/camera.cpp) 与 [相机采样实现](https://github.com/blender/blender/blob/v4.5.13/intern/cycles/kernel/camera/camera.h)。
- 当前 E6 主验证使用物理系数 `1.0`，50 mm / 36 mm / 1024 px / K=16 对应 **f/2.22222**。首轮固定系数 `0.945244` 作为历史交叉检查，不逐场景拟合；E1–E5 原始 f/2.10054 结果原样保留。Dr.Bokeh CUDA 核的 `abs(d-df)*K+1` 支持范围及软边缘会产生离散核差异，不能将其定义为 Cycles 的物理真值。
- 独立标定共 12 点，覆盖 K=4/8/16/32、前后焦点及不同层距。采用线性光边缘导数二阶矩、扣除同条件针孔方差估计有效圆盘半径。预先设定的工程容差为 `max(0.35 px, 5%目标半径)`，不是文献通用标准。10 个目标半径 ≥2 px 的点全部通过，最大偏差约 **0.1212 px**；焦平面额外半径约 **0.0052 px**。目标 1.3333 px 的点实测 1.5557 px，按原判据标记为**分辨率受限**，不计通过、不事后调整阈值。该轮尚未确定结论范围；本节末已明确验收时的声明范围。
- VideoMatte 候选的 300 对连续前景/Alpha 帧全部解码，分辨率与帧率配对通过。三帧预览观察到发丝、手臂、衣物、姿态和多人遮挡变化；它只是素材筛选，不是完整时序或边界质量验收。预览中的 checker 合成只用于筛选，正式输入使用线性光合成。
- 新入口 `scripts/generate_renderer_e6.py` 支持静态/视频前景和明确清单；对 AM-2k、头发运动、多人遮挡各抽取时间索引 0/12/24，共 9 帧完成 1024 spp OptiX 渲染。它们**不是连续帧时序验证**。针孔对齐 PSNR 为 **58.23–66.49 dB**，通过预设 45 dB 判据；AM 输入重生成的 19 个数组完全一致；仅改变前景深度的配对 RGB/alpha/mask/纹理保持相同，深度按配置改变。
- 证据汇总：`03_实验记录/records/renderer-e6-preparation-20260926.json`；输出位于 `outputs/renderer-e6-preparation-20260926/`，标定在 `calibration/`、三类抽样输入及渲染在 `short-inputs/`、素材筛选图在 `candidate_previews/`，日志在 `logs/renderer-e6-20260926/`。复用 magicbokeh 与现有 Blender，无新增依赖。

#### E6 三项前置验证、构造问题修正与完整片段结果（2026-09-26）

**先发现并修正了一个不能由对齐分数发现的构造问题**：原生成器将 VideoMatte 源画面缩小到画布内部，源画面已经截断的人物会出现悬空的矩形切边。12 个候选首帧有 7 个触及源边界；原 4 个 AM 前景也有 3 个触边。旧版虽然通过数值噪声/对齐检查，不能据此接受其构造规则。旧结果保存在 `outputs/renderer-e6-validation-20260926/` 与对应 JSON 记录中，明确标为发现问题的历史版本。

#### E7 AM-2k 前景颜色恢复：修正版验证协议

AM-2k train 提供的 `fg` / `bg` 不能视为独立物理颜色真值。E7 不再采用“以 train/fg 为 GT 直接挑选 foreground estimator”的口径，改为三层证据：

- **官方 FG 一致性评价**：`original + alpha -> F_hat` 与官方 `fg` 比较，只记作 proxy consistency；soft-alpha 边界误差可报告，但不写成真实 foreground-color accuracy。
- **可控恢复实验**：使用已知 `F_known`、Alpha 和已知背景按固定色彩空间显式构造 `I_syn = alpha*F_known + (1-alpha)*B_known`，再从 `I_syn + alpha` 恢复 `F_hat`。这里只能对这一构造条件中的恢复误差作定量结论；若 `F_known` 使用官方估计 FG，也不外推到真实自然图像颜色真值。
- **换背景视觉检查**：固定黑/白/中灰/checker及代表性 BG-20K，查看发丝、毛发、半透明边缘的旧背景残色、halo 和 color bleeding。AM validation 没有独立颜色 GT，因此只做结构和视觉合理性检查。

候选方法必须使用同一开发子集、固定参数和固定合成规则比较；不得根据正式 E7 test 或 baseline 分数反向选择。只有综合三类证据通过后才冻结 estimator，并将结论限定为**代理参考与合成构造条件下的工程可用性**。

Any-to-Bokeh 官方公开 `dataset_synthsis.py` 的 test-generation 路径启用了 `BG_test`、`merge_f25_test.json` 和 `gen_test_flag=True`；同一文件给出的 `merge_f25_test.json` 格式示例包含 `AM-2k/train` 与 `VideoMatte240K_JPEG_HD/train` 路径，同时保留了一个被注释的 VideoMatte official test clip 清单路径。由于真正的 `merge_f25_test.json` 没有公开，不能据此确认论文最终 200-video test set 的具体 source split，也不能证明其 source-level train/test 隔离。

因此 E7 当前记录以下两层方案，**尚未视为正式 scene freeze**：

- **Strict Held-out Dynamic Subset**：主测试动态部分优先使用 VideoMatte240K official `test` 的 5 个独立源视频。允许从同一 source 生成多个 25-frame clip、背景和 Focus/Depth/`K` 条件，但全部保留同一个 `source_video_id`，不把派生 clip 当作新的独立动态源；统计时保留 per-source grouping，必要时先 source 内聚合再对 5 个 source 求均值。
- **Dynamic Extended Stress Set（可选）**：若 5 个 source 的动作/发丝/衣物/遮挡覆盖不足，可额外选取 E1–E6 未使用的 VideoMatte `train` source 做动态压力测试，但必须与严格 held-out 主结果分开报告；Any-to-Bokeh 的公开生成代码存在使用 VideoMatte `train` source 的痕迹，因此不能保证其预训练阶段未见过这些源。

如果后续确实需要更多独立 held-out 动态源，优先评估另一个具有明确 test split 且提供前景/Alpha 的 video matting 数据集，而不是把大量 VideoMatte train source 直接并入主 held-out 表。正式冻结时需记录主/扩展子集、原始 source ID、scene-level 与 source-level 统计口径。


#### Future strict held-out E7 的 Any-to-Bokeh 外部 sanity check

当前 200-video public-proxy 版本的 Any-to-Bokeh sanity check 已完成。若未来建立新的 strict held-out E7，则在其场景清单、源素材、Geometry / Focus / \(K\)、GT Renderer 和指标配置冻结后，再对**该新版本**运行一次官方 Any-to-Bokeh 权重，作为独立合理性检查。

该检查只用于判断：

- 本项目冻结测试集上的 Any-to-Bokeh 指标量级是否处于可解释范围；
- 与论文公开 synthetic 结果的差异是否能由数据分布、GT Renderer、运动、Geometry / Focus / \(K\) 分布和评价实现解释；
- 是否存在 RGB/GT 对齐、帧顺序、色彩空间、Depth/Disparity、Focus/\(K\)、CoC、输出尺寸或 metric implementation 等客观实现错误。

约束：

- paper-reported numbers 与本项目结果必须分开报告，不视为同一测试集直接复现；
- 不要求两边数值接近，只比较量级、趋势和 failure case；
- 禁止为了接近论文分数而调整测试素材、场景难度、Geometry / Focus / \(K\) 分布、renderer 参数或评价阈值；
- 若冻结后发现客观实现错误，需要修改 Benchmark 时必须升级版本并重新冻结，不能静默修改；
- 当前 public-proxy 检查已经完成，因此可以直接进入 Table 1A baseline sweep；future held-out E7 另行冻结。

正式报告中可单列 **Comparison with Any-to-Bokeh reported synthetic results**，并注明本 Benchmark 受其公开合成协议启发，但不是作者官方 Synthetic Test Set 的逐样本复现。


冻结后必须固定：

- GT Renderer；

- metric implementation。

- 初步建议：保留 general，不直接安装三份 requirements。因已有明确版本冲突，可为首个复现建立 Python 3.10 专用环境，保留支持本机 GPU 的新 PyTorch 并适配旧依赖；Any-to-Bokeh 与 MagicBokeh 是否可共用须经实际验证，暂不创建三个环境。尚未建立专用环境或验证统一依赖方案。
