### 下一步：BokehMe Track A adapter recovery（计划已明确，尚未开始）

目标不是重新设计 BokehMe，而是尽量恢复 Any-to-Bokeh Table 1 中 BokehMe baseline 的统计行为，同时保持当前 200-video benchmark 的 RGB / Geometry / Focus / K / GT 不变。

#### 已从公开材料确认

- BokehMe 原生接口是 **AiF RGB + disparity + focus disparity + K + gamma**；
- 正式运行必须包含 **classical renderer + ARNet + IUNet + error-map fusion**，不能只跑 classical renderer；
- 方法按单帧独立推理，不引入额外时序平滑；
- BokehMe 原论文 quantitative setting 使用 **gamma=2.2**；
- 官方 demo 默认 `defocus_scale=10`，圆形 `ModuleRenderScatter`；
- `highlight` 是额外高光增强选项，当前定量复现默认 **关闭**；
- Any-to-Bokeh 明确把 BokehMe 作为依赖输入 geometry 的 image-based baseline，并在 noisy-depth / DAVIS 比较中与其他方法共享 geometry/control 信息。

#### Any-to-Bokeh 未公开的关键 adapter 细节

公开论文和仓库**没有给出 Synthetic Table 1 的 BokehMe inference adapter**，因此下列细节不能直接声称已知：

- 是否对 disparity 做 per-frame min-max normalization；
- focus 是否随 normalization 同步变换；
- K 是否按 disparity range 重缩放；
- Table 1 中实际 gamma；
- 是否启用 `highlight`；
- 是否对官方 demo 做了其他 preprocessing 修改。

因此本阶段定义为 **BokehMe reproduction adapter recovery**，而不是“照抄 Any-to-Bokeh 已公开脚本”。

#### 第一优先级：只恢复 signed-defocus 口径

BokehMe 官方 demo 会先对 disparity 做 min-max normalization，再计算：

\[
S = K(d-d_f)
\]

而当前 frozen benchmark 已经有固定绝对 disparity 坐标系，且 Any-to-Bokeh 直接基于该坐标计算 CoC。因此首先只比较两个有明确依据的候选，不做大网格搜索：

**Candidate A — Shared-Defocus**

\[
S_A = K(d-d_f)
\]

- 直接使用当前 PNG8 disparity / 255；
- focus 沿用现有文件名解析值；
- K 保持 4/8/16/32；
- 不做 per-frame disparity normalization；
- 保持与当前 benchmark target 完全一致的 signed defocus。

**Candidate B — BokehMe-Normalized**

\[
d'=\frac{d-d_{\min}}{d_{\max}-d_{\min}},\qquad
d_f'=\frac{d_f-d_{\min}}{d_{\max}-d_{\min}}
\]

再按官方 convention：

\[
S_B=K(d'-d_f')
\]

- disparity 和 focus 必须**一起**变换；
- 不允许只 normalize disparity 而保持旧 focus；
- K 首轮保持原值，用于恢复作者可能的 official-style convention；
- 不根据小样本成绩临时乘 K scale。

补充：若后续需要严格保持 signed defocus，可使用 `K'=K(d_max-d_min)` 与归一化 disparity 配对；它与 Candidate A 在 `K(d-d_f)` 上等价，因此当前不作为第三候选重复运行。

#### 其他参数先固定

第一轮 adapter recovery 不同时搜索 gamma / highlight：

- `gamma = 2.2`：采用 BokehMe 原论文 quantitative setting；
- `highlight = false`；
- `defocus_scale = 10`；
- circular aperture / `ModuleRenderScatter`；
- ARNet / IUNet 使用现有严格加载成功的官方 checkpoint；
- 输出 clamp 到 `[0,1]` 后 PNG8；
- 逐帧独立运行，不做 temporal smoothing。

只有当 A/B 两种 defocus convention 都无法解释论文 BokehMe 统计行为，并且有新的公开证据支持时，才考虑第二阶段 photometric candidate；当前不提前扩展 gamma 或 highlight 搜索。

### 阶段 E1：准备最小 Synthetic 数据素材

第一轮只构建 **5 个 scene × 25 帧**，不直接生成 200 个完整测试视频。

固定：

```text
Resolution = 1024 × 576
Frames = 25
Scenes = 5
Foreground source = VideoMatte240K / AM-2k
Background source = BG-20K
Focus target = 1 / scene
Blur strength K = 先固定一个中等值，暂定 K=16
Random seed = 固定
```

每个 scene 首先只生成公共输入，不生成最终 GT：

```text
scene_xxxx/
├── rgb/
├── disparity/
├── depth/          # 若当前几何能稳定转换则保存
├── alpha/
├── mask/
└── metadata.json
```

`metadata.json` 至少记录：

- foreground / background 来源；
- random seed；
- object 数量、位置和前后关系；
- per-frame geometry；
- focus target / focus value；
- K；
- resolution；
- frame count。

验收标准：

1. 5 个 scene 均能稳定生成 25 帧；
2. RGB、Alpha、Mask、Disparity 时间对应关系正确；
3. 前后景遮挡关系正确；
4. 不存在明显越界、空 Mask 或损坏帧；
5. 固定 seed 后可重复生成同一场景。

### 阶段 E5：GT Renderer Comparison

使用 E1 的同一批公共输入，只改变 GT Renderer。

```text
Synthetic RGB / Geometry / Focus / K
                ↓
          Any-to-Bokeh
                ↓
            Prediction
              /     \
             /       \
       Dr.Bokeh GT   Blender GT
```

填写：

> Table 0：GT Renderer Comparison

核心定量指标：

[

]

同时记录：

- Rendering Time；
- Hair / Thin Structure；
- Occlusion Boundary；
- Halo / Leakage；
- Color Bleeding；
- Strong Bokeh Realism；
- Temporal Stability；
- Reproducibility；
- Fairness。

### 阶段 E6：24 场景开发验证——验证 Benchmark 构造规则是否可靠

当前状态：**E6 已在声明范围内验收通过**。24 场景全流程及结构/关键帧检查已完成；小半径结论范围、开发排除清单及正式测试保留素材池的源 ID 隔离已落实。详见本节末验收记录；正式 E7 场景尚未冻结。E1–E5 已完成 Renderer 可行性验证；E6 的目标是验证正式 Benchmark 冻结前的构造协议，不能仅通过扩大样本量宣告通过。

| 组成 | 数量 | 核心目的 |
|---|---:|---|
| AM-2k 静态前景 + 受控运动 | 12 场景 | 控制变量，检查深度、遮挡、焦点及 K 的影响 |
| VideoMatte240K 动态前景 | 12 场景 | 检查真实动作、发丝、衣物边缘及 Alpha 的时间变化 |
| 独立标定画面 | 另计 | 检验不同 K、焦点和深度条件下统一映射是否成立 |

每场景延续 25 帧、1024×576。VideoMatte 提升的是时间上的真实运动；人物仍作为一个或若干二维平面进入场景，统一称为**动态分层平面合成**，不得称为真实三维人体几何。

#### 场景设计与素材隔离

- AM-2k 使用有意设计的配对场景：固定同一前景、背景及其他参数，分别只改变前景深度、背景深度、Focus 或 K；遮挡变化也需明确控制因素，不能随机凑满 12 场景。
- VideoMatte 的 12 场景覆盖头发运动、快速手臂运动、衣物边缘、姿态变化、明显 Alpha 变化及遮挡区域变化；允许一段素材覆盖多种现象，但必须记录实际覆盖情况。
- 记录源素材标识、源视频及取帧区间、变换、参数与随机种子。具体素材清单及参数组合在执行前确定，尚未选定的内容不写成已完成。
- 正式测试与 E1–E6 开发集按**源素材级别**隔离：VideoMatte 必须使用不同源视频，同一视频的不同帧段不算隔离；AM-2k 前景和 BG-20k 背景同样按原始素材隔离，裁剪或变换不能改变素材归属。

#### 统一映射与验证顺序

1. 先核对代码中 K、深度/视差的单位和归一化方式，明确焦点距离、物体深度、焦距、传感器尺寸及图像分辨率如何进入虚化尺度关系，再确定一套统一公式或统一标定规则。
2. 现有 K=16、焦点 2 m、背景 6 m、50 mm/36 mm 相机下的 f/2.10054 仅是参考标定点。固定统一规则后，用独立画面验证不同 K、焦点及前后景深度；禁止逐场景调整光圈去拟合 Dr.Bokeh。
3. 先做标定画面与短片段检查，再批量生成 24 场景。若统一规则仅在有限范围成立，明确限定 Benchmark 的有效参数区域，不为覆盖所有情况引入手工参数。
4. 以标定偏差、独立采样种子/高采样参考下的噪声和时间变化、Alpha/遮挡边缘检查为主要证据；Any-to-Bokeh 分数仅描述预测与参考的距离。24 段视频不自动构成稳定 FVD 估计的充分样本。

#### E6 准备与首轮标定结果（2026-09-26）

- 清单与预设判据：`configs/renderer-e6.json`。AM-2k 为 2 组 × 6 场景，每组含参考、仅前景深度、仅背景深度、仅焦点、仅 K、增加遮挡层；VideoMatte 为 12 个独立源视频候选，已登记帧区间及开发素材排除清单。素材、变换后屏幕尺寸与其他参数保持固定的配对用于隔离深度影响。
- 统一规则：视差采用 `d=1/z_m`，不按场景归一化；目标圆形弥散半径 `R_px=K*abs(1/z_m-1/Zf_m)`。对于当前 Cycles 透视相机、水平传感器匹配和方形像素，使用 `N=f_m²*W_px/(2*S_m*K)`。物距与焦距平面通过半径差值起作用，在解出 N 的系数时抵消；这是当前相机模型的关系，不是任意相机/深度归一化下的通式。依据为 [Blender 4.5.13 光圈转换](https://github.com/blender/blender/blob/v4.5.13/intern/cycles/blender/camera.cpp) 与 [相机采样实现](https://github.com/blender/blender/blob/v4.5.13/intern/cycles/kernel/camera/camera.h)。
- 当前 E6 主验证使用物理系数 `1.0`，50 mm / 36 mm / 1024 px / K=16 对应 **f/2.22222**。首轮固定系数 `0.945244` 作为历史交叉检查，不逐场景拟合；E1–E5 原始 f/2.10054 结果原样保留。Dr.Bokeh CUDA 核的 `abs(d-df)*K+1` 支持范围及软边缘会产生离散核差异，不能将其定义为 Cycles 的物理真值。
- 独立标定共 12 点，覆盖 K=4/8/16/32、前后焦点及不同层距。采用线性光边缘导数二阶矩、扣除同条件针孔方差估计有效圆盘半径。预先设定的工程容差为 `max(0.35 px, 5%目标半径)`，不是文献通用标准。10 个目标半径 ≥2 px 的点全部通过，最大偏差约 **0.1212 px**；焦平面额外半径约 **0.0052 px**。目标 1.3333 px 的点实测 1.5557 px，按原判据标记为**分辨率受限**，不计通过、不事后调整阈值。该轮尚未确定结论范围；本节末已明确验收时的声明范围。
- VideoMatte 候选的 300 对连续前景/Alpha 帧全部解码，分辨率与帧率配对通过。三帧预览观察到发丝、手臂、衣物、姿态和多人遮挡变化；它只是素材筛选，不是完整时序或边界质量验收。预览中的 checker 合成只用于筛选，正式输入使用线性光合成。

#### E7 AM-2k 前景颜色恢复：修正版验证协议

AM-2k train 提供的 `fg` / `bg` 不能视为独立物理颜色真值。E7 不再采用“以 train/fg 为 GT 直接挑选 foreground estimator”的口径，改为三层证据：

- **官方 FG 一致性评价**：`original + alpha -> F_hat` 与官方 `fg` 比较，只记作 proxy consistency；soft-alpha 边界误差可报告，但不写成真实 foreground-color accuracy。
- **可控恢复实验**：使用已知 `F_known`、Alpha 和已知背景按固定色彩空间显式构造 `I_syn = alpha*F_known + (1-alpha)*B_known`，再从 `I_syn + alpha` 恢复 `F_hat`。这里只能对这一构造条件中的恢复误差作定量结论；若 `F_known` 使用官方估计 FG，也不外推到真实自然图像颜色真值。
- **换背景视觉检查**：固定黑/白/中灰/checker及代表性 BG-20K，查看发丝、毛发、半透明边缘的旧背景残色、halo 和 color bleeding。AM validation 没有独立颜色 GT，因此只做结构和视觉合理性检查。

候选方法必须使用同一开发子集、固定参数和固定合成规则比较；不得根据正式 E7 test 或 baseline 分数反向选择。只有综合三类证据通过后才冻结 estimator，并将结论限定为**代理参考与合成构造条件下的工程可用性**。

#### E7 前景颜色三候选开发比较（2026-09-27，完成；方法未冻结）

本轮复用上述 **60 个 train 源 / 20 类动物**，比较 naive（original 直接当 FG）、PyMatting ML/sRGB、ML/linear。固定配置为 `configs/am-foreground-estimation.json`，在产生候选成绩前写定样本、背景分配、参数和选择规则；未改样本或按分数筛除异常。

- 三类输入：自然 original（只评代理一致性）；官方代理 FG 与已知背景在 sRGB 中合成；同一 FG/Alpha/背景在线性空间合成再编码 sRGB。后两者是显式已知输入的受控恢复，不是自然图像物理真值验证。
- 七类背景固定为黑、白、中灰、32 px checker，以及 E6 已使用的 BG train 中按缩略图亮度/对比度选出的暗、亮、高对比背景。每个源循环分配一种受控输入背景，两种色彩空间使用同一背景；评价时再换全部七类背景。七个背景不是七个独立源样本。
- 保持原图分辨率；Alpha/FG 不缩放；ML 只接收 image 和 alpha。固定 PyMatting 1.1.16，默认 regularization=1e-5、small iterations=10、big iterations=2、small size=32、gradient weight=1。输出为未乘 Alpha 的 RGB，clip [0,1]；本次所有输出实际均已在范围内。无参数搜索。
- **主指标**：0.05<Alpha<0.95 区域内 `mean(abs(Alpha*(F_est_linear−F_ref_linear)))`，逐源等权平均。它等价于线性新背景重合成 MAE，与新背景无关。另保存 sRGB/linear FG MAE/MSE/PSNR、0<Alpha<1 区域误差、有限差分梯度误差、Alpha 加权误差、七背景显示域重合成误差与耗时；梯度定义不冒称官方 GRAD 实现。

| 输入/证据类型 | naive 主 MAE↓ | ML/sRGB 主 MAE↓ | ML/linear 主 MAE↓ | ML/sRGB 优于 ML/linear 的源数 |
|---|---:|---:|---:|---:|
| 自然图：官方 FG 代理一致性 | 0.049747 | **0.013544** | 0.018864 | 59/60 |
| sRGB 可控合成恢复 | 0.068414 | **0.014084** | 0.028344 | 60/60 |
| linear 可控合成恢复 | 0.071414 | 0.024178 | **0.013536** | 4/60 |

两个 ML 候选的均值均优于 naive。ML/sRGB 相对 naive 的逐源主指标胜出数依次为 60/60、60/60、59/60；ML/linear 三类输入均为 60/60。自然图 soft FG sRGB PSNR 分别为 naive 13.2552、ML/sRGB 24.5945、ML/linear 22.0604 dB，**只能叫代理一致性 PSNR**。

**视觉检查及失败案例**：生成每源三种输入的固定边缘比较图与 overview，共 240 张，全部可解码。实际查看每类预先选定第一源的黑背景 crop（20 张），另查看 `m_190c3511`、`m_c8ce1ddc`、`m_f820db9a`、`m_1e7e2619` 的自然图七背景面板，以及 `m_72b29bf5` 的两类受控输入七背景面板；不宣称人工全览全部像素或全部图。naive 在多处毛发保留旧背景残色，ML/sRGB 多处减轻；ML/linear 在部分自然图产生暗/偏红边。**骆驼 `m_72b29bf5` 的 checker 输入在两个 ML 结果中均残留棋盘纹理**，保留为受控合成失败案例。自然图代理自身也可能含颜色误差；Alpha=0 的裸 FG 颜色不作为可识别真值或视觉合格标准。

#### E7 VideoMatte 动态源策略（待冻结）

Any-to-Bokeh 官方公开 `dataset_synthsis.py` 的 test-generation 路径启用了 `BG_test`、`merge_f25_test.json` 和 `gen_test_flag=True`；同一文件给出的 `merge_f25_test.json` 格式示例包含 `AM-2k/train` 与 `VideoMatte240K_JPEG_HD/train` 路径，同时保留了一个被注释的 VideoMatte official test clip 清单路径。由于真正的 `merge_f25_test.json` 没有公开，不能据此确认论文最终 200-video test set 的具体 source split，也不能证明其 source-level train/test 隔离。
