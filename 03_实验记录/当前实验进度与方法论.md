## 1. 研究主线

本项目面向云端离线精修，研究如何利用高帧率 RGB 视频和低帧率粗糙深度，生成主体清晰、边界自然、虚化可控且时间上稳定的视频。深度时空补全、主体与边界建模、虚化渲染和时序一致性是相互关联的研究问题。

当前处于 **baseline 评价体系收尾阶段**：先完成公开方法复现和固定条件下的比较，明确现有方法的表现与问题，为后续 Ours 提供稳定的比较基础。课题原文提出的共享时序表征、深度/Alpha/虚化三个分支，以及物理渲染结合神经残差，仍是候选路线；具体方法将结合实验认识确定。

后续研究连接为：**现有方法比较 → 识别值得解决的问题 → 实现并验证 Ours → 在独立且更贴合课题输入的 benchmark 上验证泛化。** 当前复现数据上的比较和未来独立验证分开报告。

### 已确认的执行顺序

1. **DAVIS Real-world / VEPI**：先确定公开可复现的评价清单与 VEPI 操作定义，再运行六种主要 baseline。沿用已确定的作者公开代码操作口径，记录与论文文字的差异；正确处理对象 ID mask，并区分评价区域和推理输入的权限。
2. **Efficiency**：统一分辨率、片段长度、预热、重复次数及 Core/E2E 计时范围。GPU 方法尽量在同一设备比较，DeepLens CPU 单独标注；当前 Dr.Bokeh 效率跟随 GT Alpha 主表配置。
3. **Track B Clean Low-FPS**：先冻结同一个简单、非学习式的时间补齐方法，只改变几何时间采样率，再批量评价各 baseline；本轮不叠加噪声、孔洞和边界破坏。
4. **Baseline Table Freeze**：冻结 Table 1A、Table 1B-Clean、Table 2、Table 3、Table V 中除 Ours/BokehCrafter-deferred 外的可复现实测项。后续除客观实现错误外，不根据 Ours 成绩回调配置或评价口径。
5. **Ours**：开始正式实现、训练和迭代，将各版本结果补入同一套冻结表格。

当前首先完成其余DAVIS方法输入预检（DeepLens native-default aperture0.5已冻结），再运行50×25正式评价；之后依次落实Efficiency测量和Track B公共时间补齐。完整 OPPO-style Mild/Medium/Severe 退化需要真实或有依据的传感器统计，future strict held-out E7 另行设计；二者及 BokehCrafter 均不新增为 Ours 前置门槛。具体执行要求沿用[统一评价协议](Benchmark与Baseline统一评价协议.md)。

## 4. 结果讨论

### 已有结果说明了什么

- **输入与适配方式对结果有实质影响。** Dr.Bokeh 在同 200 段上的输入对照中，GT Alpha 相对 Full-public 的 PSNR 在 198/200 段改善。该证据支持分割输入及其引起的后续分层、修复与补全过程是差异的重要来源；已知图层分支同时改变多个因素，应按整体输入条件解释。见[输入效应分析](records/drbokeh-input-effect-analysis-20260929.json)。
- **当前已恢复可比较的结果，但论文性能版图尚未完全恢复。** MPIB、BokehMe、BokehDiff 的候选选择及 DeepLens 结果均已记录依据，部分绝对分数和方法排序仍与论文不同。现阶段成果是声明条件下的公开代理复现；当前 200 段参与过配置选择，属于复现开发证据。详见统一协议中的 Table 1A / Table V。
- **控制能力和视觉问题需要结合数值理解。** DeepLens 单级路径在 K16/32 上全部达到 aperture 上限，虚化不足及部分亮度、边缘偏差仍可观察到；BokehDiff 的复核保留了弱虚化不足、强虚化过度平滑和细节重绘等现象。它们说明现有方法在控制响应与视觉保真之间仍有值得分析的问题，尚不能据此归纳所有方法的统一失效原因。见[DeepLens 复核](records/deeplens-track-a-final-review-20260929.json)与[BokehDiff 复核](records/bokehdiff-final-review-20260929.json)。

### 对后续研究的启发

**基于现有证据的判断**：后续方法设计值得同时关注输入几何、主体边界和最终渲染之间的关系；应结合整体指标与具体视频表现识别主要瓶颈。现阶段已具备开展这种分析的比较基础，尚未验证 Ours 的具体模块或创新效果。

**待下一阶段回答的问题**：这些表现能否延续到真实视频？几何帧率降低后，各方法如何退化？效果与计算成本之间有什么关系？DAVIS、Efficiency 和 Track B Clean 将分别补充这些证据，再据此收敛 Ours 的具体研究重点。
