## 稳定问题背景

课题原文面向云端离线精修，以 OPPO 手机双目系统记录的高帧率 RGB 视频与低帧率粗糙深度为输入，目标是研究深度补全、主体及边界处理、可控虚化和时序一致性的统一视频虚化方法。

原文已提出共享时序表征、深度/alpha/虚化三个输出分支、物理渲染与神经残差结合的候选路线，并提出数据集（数据制作方案）、训练模型与代码等交付目标。原文计划为 2026 年 10—12 月完成数据准备与 baseline 搭建，2027 年 1—5 月优化方法与中期检查，2027 年 6—9 月提升效果和效率并结题。这些是提案内容，具体实现、可行性、时间安排和最终验收口径仍需确认。

材料来源：`00_项目资料/OPPO影像课题提报模板_给学生.pdf`，研究计划部分。此前项目规则记录服务器已建立分层存储链路；本次仅检查 Windows clone，未核实服务器状态，使用时以对应机器的本地说明和实际路径为准。

- 官方源码：`third_party/any-to-bokeh`（https://github.com/vivoCameraResearch/any-to-bokeh，`f7a1695`）、`third_party/MagicBokeh`（https://github.com/vivoCameraResearch/MagicBokeh，`c672e63`）、`third_party/BokehDiffusion`（https://github.com/atfortes/BokehDiffusion，`45a01fe`）。均为保留独立 Git 信息的浅克隆，通过本 clone 的 `.git/info/exclude` 排除，不随主仓库提交。
- 实际环境：`D:\develop\Miniconda\envs\general\python.exe`，Python 3.13.14，PyTorch 2.8.0+cu128，torchvision 0.23.0+cu128，NumPy 2.4.4；`pip check` 通过。缺少 diffusers、transformers、accelerate、OpenCV、xformers。未修改现有环境。
- 硬件：RTX 5060 Laptop GPU，约 8 GB 显存，系统内存约 15.4 GiB；检查时可用内存约 2.3 GiB。PyTorch 可识别 CUDA 设备，包含 sm_120 支持；未运行模型或验证实际显存峰值。
- 官方环境均采用 Python 3.10，但版本不同：Any-to-Bokeh 使用 torch 2.4.1、diffusers 0.25.0、transformers 4.32.1；MagicBokeh 使用 torch 2.3.0、diffusers 0.25.0、transformers 4.46.0；Bokeh Diffusion 使用 torch 2.6.0、diffusers 0.32.2、transformers 4.53.0。三份固定依赖不能原样共存。
- MagicBokeh 的 NumPy 1.26.0 明确要求 Python <3.13；xformers 0.0.26.post1 绑定 torch 2.3.0。其 requirements 同时固定 gradio 6.11.0 和 huggingface_hub 0.23.2，而前者要求 Hub >=0.33.5，存在内部冲突。单纯新建环境也不能解决全部问题。
- Any-to-Bokeh：自带示例帧及预处理视差；仍缺作者 UNet/VAE 权重及 `stabilityai/stable-video-diffusion-img2vid-xt` 基础模型缓存。入口 `test/inference_demo.py` 使用 `local_files_only=True`，默认 1024×576、8 帧分组、64 个加载进程，需针对本机调整并实测显存。自有视频另需 Video-Depth-Anything、目标掩码方法及相应权重。
- MagicBokeh：自带 3 组图像、深度和掩码；最小推理需 SD2.1-base 与 `LinxiaoShi/Magicbokeh` 的 `lora.pkl`。自有图像预处理另需 DAdepth.pth、LDF model-40 和 ResNet50 权重（或使用交互选焦入口）。推理采用 512×512 分块，8 GB 可行性尚未实测；旧版模型对象的 torch.load 调用需核对新版 PyTorch 兼容性。当前仓库未见完整训练入口。
- Bokeh Diffusion：公开入口是 `inference_flux.py`，需 FLUX.1-dev（需用户获得 Hugging Face 模型访问许可）及 `atfortes/BokehDiffusion` 适配器。默认整体加载到 GPU；FLUX 的 12B 主体仅 BF16 参数即约 24 GB，无法原样放入 8 GB 显存。量化/卸载需额外适配，不能直接保证本机可运行；训练代码在官方 TODO 中仍未发布。README 要求 flash-attn，但当前适配器实际使用 PyTorch 原生 scaled_dot_product_attention，不宜直接判定该扩展为最小推理必需。
- 初步建议：保留 general，不直接安装三份 requirements。因已有明确版本冲突，可为首个复现建立 Python 3.10 专用环境，保留支持本机 GPU 的新 PyTorch 并适配旧依赖；Any-to-Bokeh 与 MagicBokeh 是否可共用须经实际验证，暂不创建三个环境。尚未建立专用环境或验证统一依赖方案。
