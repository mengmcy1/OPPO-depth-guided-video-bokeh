## 论文信息

- **题目**：BokehCrafter: Taming Video Diffusion Models for Controllable Bokeh Rendering
- **会议**：AAAI 2026
- **仓库原文**：`01_文献/03980-AAAI26.WangQ-CV.pdf`
- **记录目的**：判断该工作对当前项目 Q1～Q11 的帮助，重点关注视频时序、动态对焦、数据构造、Depth / Disparity 误差敏感性，以及视频 Backbone / Temporal Modeling。

---

# 1. 论文主要解决什么问题

BokehCrafter 面向**视频 Bokeh Rendering**。

它主要针对三个问题：

1. 单图 / 逐帧 Bokeh 方法容易在视频中产生 flicker；
2. 依赖 Depth / Disparity 的方法会受到深度误差传播影响；
3. 传统 focal distance、blur size 等参数控制不够直观。

因此它采用：

[
V_{AiF}+I_{ref}+T
ightarrow
V_{Bokeh}
]

其中：

- (V_{AiF})：All-in-Focus Video；
- (I_{ref})：Reference Bokeh Image；
- (T)：Text Instruction；
- (V_{Bokeh})：最终 Bokeh Video。

与我们的方案不同，它推理阶段不显式使用 Depth / Disparity，也没有 Depth Head、Alpha Head 和 Physical Renderer。

---

# 2. 核心网络结构

整体流程可以概括为：

```text
All-in-Focus Video
        ↓
   Video VAE Encoder
        ↓
    Video Latent
        ↓
      Add Noise
        ↓
   Denoising U-Net
        ↑
        │
 ┌──────┴─────────┐
 │                │
Text          Reference Image
 │                │
CLIP Text      CLIP Image
Encoder         Encoder
 │                │
F_txt          F_img
                  ↓
              Q-Former
                  ↓
                F_bok
 │                │
 └────── TIF ─────┘
        ↓
  Conditional U-Net
        ↓
   VAE Decoder
        ↓
  Bokeh Video
```

参考图并不是直接用于传递场景内容，而是通过 Q-Former 尽量抽取：

- Blur Pattern；
- Blur Intensity；
- Bokeh Appearance；

等风格信息。

# 3. Text-Image Fusion 的启发

论文中的 TIF（Text-Image Fusion）不是简单拼接两种条件。

其思路是：

[
F_{out}
=
TCA(F_{in},F_{txt})
+
ICA(F_{in},F_{bok})
]

即：

- Text Condition 与主特征做 Cross-Attention；
- Bokeh Image Condition 与主特征做另一组 Cross-Attention；
- 最后再融合。

对我们 RGB + Depth 的直接结论并不是“应该照搬 Cross-Attention”，但它提供一个通用启发：

> 多模态特征不一定要在输入阶段直接拼成一个 Token，可以保留各自表示，再通过条件注入 / Cross-Attention 进入共享主干。

因此它可作为未来 Q1 / Q3 中多模态融合方式的参考范式，但不能视为已解决方案。

---

# 4. 对视频时序一致性的处理

BokehCrafter 最值得关注的一点，是它并没有把时序一致性完全依赖于显式 Optical-Flow Temporal Loss。

其核心时序稳定性来自：

> Video Diffusion Backbone 本身的 Temporal Attention / Video Prior。

也就是说：

[
oxed{	ext{Temporal Feature Modeling}}
]

本身就能够降低逐帧独立处理带来的 flicker。

这对我们的方案有一个重要启发：

```text
Video Transformer / Temporal Attention
        ↓
作为第一层时序稳定保障

Temporal Loss
        ↓
如果需要，再作为额外约束
```

不能把全部时序一致性问题都压给一个 Warp Loss。

---

# 5. Temporal Consistency ≠ Temporal Constancy

论文的 Temporal Consistency 评价思路尤其值得记录。

它不是简单要求：

[
Output_t approx Output_{t+1}
]

而是关注：

[
(F^{GT}_{t+1}-F^{GT}_{t})
-
(F^{pred}_{t+1}-F^{pred}_{t})
]

即判断：

> **预测视频的帧间变化，是否接近 GT 视频真实应该发生的帧间变化。**

因此：

[
oxed{
Temporal Consistency

eq
Temporal Constancy
}
]

更合理的目标是：

[
oxed{
Predicted Change
approx
Real Change
}
]

这与我们 Q6 中的核心担忧一致：

例如人物向镜头移动，真实 Depth 本来就应该变化，不能因为相邻两帧 Depth 不一样就直接视为 flicker。

但是需要注意：

> 论文这里主要给出的是视频 Bokeh 的评价思路，并没有直接提供我们的 Depth Temporal Training Loss。

它没有解决：

- Occlusion；
- Disocclusion；
- Scene Flow；
- Optical Flow Visibility Mask；
- 真实 Depth Change 的显式建模。

所以 Q6 仍未完全解决。

---

# 6. Dynamic Focus

论文的数据集区分：

- Static Focus；
- Dynamic Focus。

这说明一个正确的视频 Bokeh 本身就可能出现：

[
Blur_t
eq Blur_{t+1}
]

因为用户可能主动改变对焦点。

这一点对我们 Q4 和 Q6 都很重要。

对 Q4：

[
oxed{	ext{Alpha 的图层含义}}

eq
oxed{	ext{当前 Focus 选择}}
]

同一个人物 / 图层的 Alpha 可以不变，但随着：

[
FocusDistance(t)
]

改变，其清晰程度可以变化。

对 Q6：

> Bokeh 随时间变化不一定是错误闪烁，也可能是正确的 Dynamic Focus。

---

# 7. VBS 数据集与 Q5

论文构建了 VBS（Video Bokeh Scenes）数据集。

基本构造方式为：

```text
All-in-Focus Video
+
Disparity / Geometry
        ↓
Bokeh Rendering Engine
        ↓
Bokeh Video GT
```

然后进一步加入：

- 不同 focal distance；
- 不同 blur size；
- Static Focus；
- Dynamic Focus；
- Text Instruction。

这一点对 Q5 很有价值：

> Synthetic Bokeh GT 不仅可以用于单图，也可以扩展到视频级数据构造。

因此我们后续如果实际数据缺少真实 Bokeh GT，可以考虑：

[
RGB Video + Geometry
ightarrow
Renderer
ightarrow
Synthetic Bokeh Video
]

但 Synthetic-to-Real gap 仍然存在，不能默认 Renderer 生成结果完全等价于真实镜头 Bokeh。

---

# 8. Depth 与 Blur Radius 的关系

论文数据构造中使用类似：

[
r
=
K
left|
rac1z-rac1{z_f}
ight|
]

的关系，其中：

- (z)：场景点深度；
- (z_f)：焦平面深度；
- (K)：Blur Size 相关系数。

这对 Q8 有重要启发：

> Bokeh Renderer 真正自然使用的几何量，不一定是简单的 (z-z_f)，而可能更接近 inverse-depth / disparity 类关系。

因此 Q8 后续不能只问：

> Depth Head 是否输出“米制 Depth”？

还应该问：

> Renderer 最自然需要哪一种几何表示？

这进一步支持我们把两个问题分开：

1. 输出是 Depth / Inverse Depth / Disparity？
2. 其绝对尺度、单位、标定关系是否已知？

# 9. 对错误 Depth / Disparity 的敏感性

论文指出依赖 Disparity 的 Bokeh 方法会明显受到输入几何误差影响，并进行了 corrupted disparity 相关实验。

这对 Q10 是比较直接的支持：

[
oxed{
Coarse Depth

eq
Ground Truth
}
]

因此我们设计：

```text
Depth
+
Mask
+
Confidence
```

作为输入是有实际问题背景的。

不过 BokehCrafter 自己的解决方法是：

> 推理阶段直接不使用 Disparity。

因此它并没有回答：

- Mask 怎么进入网络；
- Confidence 怎么加权；
- Coarse Depth 应不应该参与 Loss；
- 高置信 / 低置信区域如何区别处理。

Q10 的具体方法仍然需要查 Depth Completion / Refinement / Confidence-aware Depth 文献。

---

# 10. Backbone / Temporal Modeling 对 Q9 的启发

BokehCrafter 的实验表明 Video Prior / Temporal Attention 对视频 Bokeh 时序稳定性有明显帮助。

因此未来 Q9 调研 Backbone 时，除了记录：

- Spatial Resolution；
- Dense Prediction；
- Multi-scale Feature；
- Decoder；

还应该额外记录：

```text
Temporal Modeling 是什么？
→ Temporal Attention
→ Factorized Spatial / Temporal Attention
→ 3D Attention
→ Recurrent Propagation
→ Frame-wise + Temporal Fusion
...
```

这与我们当前：

[
Spatial Attention
+
Temporal Attention
]

的总体方向相容。

但是 BokehCrafter 最终输出 RGB Bokeh，而不是 Dense Depth / Alpha，所以不能据此直接证明 Video Diffusion Backbone 适合我们的多任务 Dense Prediction。

---

# 11. 工程上的限制

Video Diffusion 需要多步 denoising，因此推理成本较高。

这与我们项目希望：

```text
一次 Forward
↓
Depth + Alpha + Bokeh
```

的工程路线差别较大。

因此 BokehCrafter 更适合作为：

- 视频时序建模参考；
- 数据构造参考；
- Bokeh 控制参考；
- 时序评价参考；

而不太适合作为我们第一版网络 Backbone 的直接候选。

# 13. 对当前项目最值得保留的启发

## 启发 1：时序一致性不等于帧间不变化

应更关注：

[
Predicted Temporal Change
approx
Real Temporal Change
]

这一原则可以直接写入 Q6 的后续调研结论。

---

## 启发 2：Video Backbone 本身就是时序稳定性的重要来源

Temporal Attention / Video Prior 可以在 Feature Level 抑制逐帧独立处理产生的 flicker。

因此 Temporal Loss 不应是唯一的时序机制。

---

## 启发 3：Dynamic Focus 应纳入数据和任务设计

视频 Bokeh 中正确的 blur 本身就可能随时间变化。

因此未来训练 / 测试数据最好同时覆盖：

- Static Focus；
- Dynamic Focus。

---

## 启发 4：视频级 Synthetic Bokeh Data 可行

利用：

[
RGB Video+Geometry
ightarrow
Renderer
ightarrow
Bokeh Video
]

构造大规模训练数据是现实路线。

---

## 启发 5：错误 Depth / Disparity 会直接污染 Bokeh

这一点强化了我们：

[
Depth+Mask+Confidence
]

设计的必要性。

但具体 Mask / Confidence 怎么融合仍未得到解决。

---

# 14. 当前结论

BokehCrafter 对我们的直接价值主要集中在：

[
oxed{
Q4, Q5, Q6, Q8, Q9, Q10
}
]

其中最重要的是 **Q6**：

> 论文提供了很强的旁证：Temporal Consistency 不应理解为让相邻帧输出尽可能不变，而应该让预测变化与真实变化一致。

同时它还告诉我们：

> 时序稳定既可以来自 Temporal Loss，也可以来自 Video Backbone 本身的 Temporal Modeling。

这篇论文不适合用于解决：

- Q1 Token Merging Dense Recovery；
- Q2 Depth → Alpha Cross-task Guidance；
- Q3 Low-FPS Depth Propagation；
- Q11 Multi-task Sharing。

这些问题需要继续查其他方向的文献。
